# 마크 찾기 모델 — 앱에서 어디에 어떻게 쓰이나

2026-11-18 기준. 학습 과정과 모델 자체의 정확도는 `docs/마스킹-학습-진행상황.md`에 있다.
이 문서는 **그 모델을 앱에 붙인 뒤 무엇이 달라졌는지**만 다룬다.

---

## 한 줄

모델은 사진에서 **«가려야 할 글자·마크가 있는 자리»를 네모로 찾는다.** 글자는 못 읽는다.
앱은 이 네모를 **보정 단계 두 곳**에서 «어디를 다시 그릴지» 정하는 데 쓴다.

| 쓰는 곳 | 전 | 후 |
|---|---|---|
| ① 「로고 지우기」 | 가슴 로고만 지움 | 소매·바지·가방·명찰까지 지움 |
| ② 「배경 교체하기」 | 배경 전체를 새로 그림 | 위험한 간판 자리만 빈 간판으로 |

진단(위험도 점수)에는 쓰지 않는다. 진단은 예전 그대로다.

---

## 모델 파일

| | |
|---|---|
| 모델 | RF-DETR Medium, 한 종류(«가릴 자리»), int8 |
| 크기 | 41MB |
| 어디서 받나 | 배포본: Supabase `ai-shadow-dev` 프로젝트의 공개 버킷 `models/mark-int8.onnx`<br>로컬(localhost): `public/models/mark-int8.onnx` (gitignore — 저장소에 없음) |
| 어디서 도나 | **폰 브라우저 안** (onnxruntime-web). 사진은 이 단계에서 밖으로 나가지 않는다 |
| 언제 받나 | 「로고 지우기」나 「배경 교체하기」를 **처음 누를 때 한 번.** 이후 폰에 저장(Cache API) |
| 속도 (안드로이드 10, 삼성 인터넷) | 받기 2.5초(와이파이) · 사진 1장 약 3초 |

**모델을 못 받으면** (Supabase가 꺼졌거나 네트워크 문제) 앱은 깨지지 않는다.
두 기능 모두 모델이 없던 예전 방식으로 돈다.

> Supabase 무료 플랜은 일주일 안 쓰면 프로젝트가 멈춘다. 발표·심사 전에 켜져 있는지 확인할 것.

## ① 「로고 지우기」

```
누름 → 동의 → [폰 안에서]
  얼굴·손 찾기          (예전부터)
  옷 자리 찾기          (예전부터)
  가슴 로고 찾기        (예전부터, findLogoRects)
  모델 네모 찾기        ← 새로
      └ 버리는 네모: 얼굴을 품은 것 · 가장 큰 얼굴 폭의 1.5배보다 긴 것 · 옷 위가 60% 안 되는 것
  남은 자리만 흰색(다시 그림) → 얼굴·머리·목·손은 마지막에 검게
  → AI 보정으로 전송 → 결과를 마스크 안쪽에만 합성
```

- **왜 네모를 버리나:** 모델이 «사람 전체»를 네모로 자주 잡는다(정답표 103장에서 625개 중 110개가 얼굴을 품음).
  그대로 쓰면 옷 전체가 다시 그려진다.
- **좋아진 것:** 예전 방식이 남기던 가슴 아래 명찰, 소매·바지 로고, 가방끈 이름표를 그 자리만 연다.
- **안전:** 어떤 네모가 들어와도 얼굴은 0픽셀 열린다(`test/mark-model.js`).

코드: `index.html`의 `detectMarkBoxes` · `markRectsOnClothes` · `runEmblemRemoval`

## ② 「배경 교체하기」 → 간판 자리만

```
누름 → 동의 →
    [폰 안에서] 모델 네모 찾기
      └ 버리는 네모: 얼굴을 품은 것 · 절반 넘게 사람 위인 것 · 사진 절반보다 큰 것 · 겹친 것
      └ 최대 30개
    [Claude, 약 4원] 네모마다 잘라 키운 조각을 한 장에 모아 «번호마다 무슨 글자인지»만 묻는다
      └ 얼굴은 자르기 전에 검게 가린다 (진단과 같은 maskFaces)
    [폰 안에서] 위험한 글자만 고른다 — 앱의 장소 글자 판정(isPlaceWord) 그대로
      └ «햇살어린이집» 고름 · «스타벅스»(지점 없음) · «(판독 불가)» · 글자 없음은 안 고름
    고른 네모 ∩ 사람 밖 → 흰색. 얼굴·손은 검게
    간판 자리를 미리 바탕색으로 칠해서 보냄 → AI에게 «빈 간판»만 그리게 함
  → 「배경 전체 바꾸기」 단추가 나타난다. 누르면 그 결과 위에서 배경 전체를 새로 그린다
    진단에서 알아볼 수 있는 장소(랜드마크)가 나왔으면 안내에 «이곳은 간판이 없어도 «○○»로 알아볼 수 있어요» 경고
  고를 간판이 없으면 → 배경 전체 교체 (예전과 같음)
배경 전체 교체 뒤: 사람 둘레 «넓혀서 막은 띠»에 남은 옛 배경을 새 배경 색으로 채운다 (fillHaloFromBackground)
```

- **랜드마크가 있어도 간판부터:** 처음에는 랜드마크가 보이면 바로 배경 전체로 갔다. 폰 테스트(삿포로 거리)에서
  거리가 통째로 다른 곳이 되어 쓸 수 없는 사진이 됐다. 이제 간판만 바꾸고 경고한 뒤, 더 가릴지는 부모가 고른다.
- **사람 둘레 얼룩:** 배경 교체는 사람 경계가 흔들려도 다시 그리지 않도록 사람을 넓혀 막는다. 그 띠에 옛 간판 색이 남아
  어깨 옆에 초록·빨간 얼룩이 보였다. 합성 뒤 띠를 바깥 새 배경 색으로 채운다 — 띠에 남은 옛 배경 77% → 0%,
  사람·얼굴 픽셀 0개 바뀜 (`test/bg-halo.js`, 새 배경을 단색으로 바꿔 잼).

- **짝짓기:** 모델은 위치만 알고 글자를 못 읽는다. 진단(Claude)은 글자를 읽지만 위치를 9칸으로만 안다.
  그래서 네모에 번호를 붙여 Claude에게 읽게 한다. **위험한지는 Claude가 아니라 앱이 정한다**(판정은 한 곳에만).
- **왜 빈 간판인가:** AI가 그린 한글은 «쉘붇라옵»처럼 깨지고, 말이 되는 이름은 실제 있는 다른 곳을 가리킬 수 있다.
  «글자 쓰지 마»라고 부탁하지 않고, 보내기 전에 글자를 지워 두는 «차단» 방식이다
  (테스트 사진: 원본의 어두운 글자 획 23.7% → 보낸 사진 0.0%).

코드: `index.html`의 `signRectsOffPerson` · `drawCropSheet` · `pickPlaceSigns` · `buildSignMask` · `runSignReplace`,
`server/server.js`의 `/api/read-sign-boxes`

## 잰 값

### 간판만 지우기 — 팀이 «가려야 한다»고 표시한 간판 중 몇 개를 열었나

시험 102장 중 간판 사진 87장(실사, 학습에 안 씀). 정답 간판 537개. AI 보정은 하지 않고 마스크만 비교했다.

| 방법 | 연 정답 간판 |
|---|---|
| 사진 통째로 번호만 그려 읽기, 12개까지 | 152 / 537 (28%) |
| 잘라서 확대해 읽기, 30개까지 (지금) | 178 / 537 (33%) |
| 같은 방법을 원본 사진(2560px)으로 — 겹치는 25장만 | 60 / 160 (38%) — 줄인 사진은 34% |

어디서 빠지나 (처음 방식 기준): 모델이 못 찾음 21% → 거르기·개수 제한 19% → Claude «판독 불가»·«글자없음» 30%.

- 정답 간판 밖을 연 넓이: 보통 사진의 0.9%, 90%가 4.5% 이하. **엉뚱한 곳은 거의 안 연다.**
- 확대·원본의 효과는 흔들림(같은 사진도 다시 읽으면 몇 %씩 바뀜) 안쪽이다. **확대로는 크게 못 고친다.**
- 팀 정답은 «입장», «2F», «주차장»까지 넓게 잡았다. «위치를 알려 주는 간판»만 세면 비율이 더 높을 수 있다.
- **홀드아웃이 깨졌다:** 확대 방식은 시험 세트 결과를 보고 만들었고 같은 세트로 다시 쟀다.

측정 비용: 합계 777원 (Claude 읽기만, 한 장 약 4원).

### 로고 지우기
정답표 103장으로 모델 켬/끔 마스크를 비교해 눈으로 봤다(거르기 규칙을 여기서 정했으므로 이 세트는 측정용이 아니다).
**실제 보정 품질은 아직 재지 않았다** — 로고·명찰이 달린 옷을 입은 아이 사진으로 재야 한다.

## 한계 (알고 쓸 것)

1. **간판만 지우기는 위험한 간판의 3분의 1 정도만 찾는다.** 결과 문구가 지운 간판 이름을 보여 주고
   «다른 간판이 남아 있지 않은지 확인해 주세요»라고 안내한다. 부족하면 배경 전체 교체를 써야 한다.
2. 로고 지우기: 작은 가슴 배지를 모델이 못 보면, 예전의 «가슴 띠 통째로» 대신 모델 자리만 열어 배지가 남을 수 있다.
3. 로고 지우기: 나무 입간판을 옷으로 착각해 그 글자를 연 사례가 한 장 있다.
   **칼라 여밈:** 폴로 교복의 하늘색 단추 여밈을 로고로 잡아 다시 그리면, 명치에 뭉개진 자국이 남는다(폰 테스트 11-18).
   모델 탓이 아니라 예전 로고 찾기 규칙(`findLogoRects`) 탓이다. «목에 붙은 덩어리 빼기» 규칙을 시험했지만,
   정답표에서 목걸이·멜빵 이름표 3개와 태권도 메달 2개까지 빠져서 되돌렸다. 놓치는 것이 더 나쁜 실패라서다.
4. 모자 로고는 확인하지 못했다(사진 부족).
5. 처음 한 번 41MB를 받는다. 받는 동안 진행 표시가 없다.
6. **아이폰은 아직 재지 않았다.** 메모리 제한이 가장 빡빡한 기기다.
7. 영상(프레임 단위)은 1장 3초라 폰에서 안 된다 — 발표에서는 확장 계획으로만.
