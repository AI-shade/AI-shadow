# 합칠 것이 두 개가 아니라 세 개입니다

같은 저장소 안에 **서로 다른 구현 세 개**가 있습니다. 그중 둘은 단일 HTML,
하나는 Next.js 앱입니다. 파일을 합치는 문제가 아니라 **어느 구조로 갈지**
정하는 문제입니다.

기준: `main` cfd5141 / `hyeon-latest` b60604b / `hyeon-version` 999d92c

---

## 1. 세 갈래

`geunoh1017-sketch/Deepfake` 한 저장소 안에 있습니다. 어느 것도 아직 지워지지 않았습니다.

| | main | hyeon-latest | hyeon-version |
|---|---|---|---|
| 커밋 | `cfd5141` | `b60604b` | `999d92c` |
| 구조 | Next.js 15 · React 19 · TS | index.html + Express | index.html 단독 |
| 코드 | 4,662줄 | 6,766줄 | 3,479줄 |
| API | 라우트 6개 | 라우트 11개 | localhost 고정 8곳 |
| 테스트 | vitest 15개 파일 | 23개 파일 · 495개 | 없음 |
| 배포 | 설정 없음 | **버셀에서 동작 중** | 불가 (5번 참고) |

## 2. main은 무엇인가

이게 이 문서를 다시 쓴 이유입니다. 처음에는 `index.html` 두 개를 비교했는데,
**`main`에는 `index.html`이 아예 없습니다.**

`app/` · `lib/` · `tests/` 구조에 TypeScript로 짜여 있습니다. 단일 HTML 두 개와는
파일 하나도 겹치지 않습니다. **`git merge`로 합쳐지는 관계가 아닙니다.**

```
app/api/          diagnose · caption · correct · verify
                  location-check · schedule-pattern
app/components/   BeforeAfterSlider · LoadingScene · PhoneMockup
                  ScoreGauge · ScrollFade · SelfCheckCarousel
app/diagnose/     page.tsx · result/page.tsx · DiagnoseContext.tsx
lib/              claude.ts · falai.ts · googleVision.ts · prompts.ts
                  localVision/{faceDetection, ocr, imageEditing}.ts
tests/            vitest 15개 파일
```

판독 방식도 다릅니다. `hyeon-latest`는 **Claude Vision**으로 사진 속 글자와
교복·엠블럼을 읽지만, `main`은 **Google Vision 웹 검색**으로 그 사진이 인터넷의
알려진 장소와 맞는지를 확인합니다(`location-check`). 서로 다른 접근이고,
둘 다 쓸모가 있습니다.

> 세 갈래 모두 코드를 열어 확인한 결과입니다.

### 옷 바꾸기 — 셋 다 있지만 방식이 다릅니다

| | 무엇을 고르나 | 어떻게 처리하나 |
|---|---|---|
| **main** | `uniform`(다른 학교 교복) / `casual`(일상복) + 세기 3단계(subtle·moderate·strong) | Claude가 **사진을 보고** 영어 지시문을 쓰고, flux-**kontext**가 사진 전체를 다시 그림 |
| **hyeon-latest** | 고를 것 없음 (프롬프트 고정) | 옷 영역만 **마스크**로 잡아 flux-**fill**로 그 부분만 교체 |
| **hyeon-version** | 컬러웨이 4가지 + 엠블럼 처리 2가지 | — |

이게 단순한 UI 차이가 아닙니다.

- **kontext**(main)는 **사진 전체를 다시 그립니다.** 그래서 프롬프트에
  *"preserve facial features with pixel-level accuracy"*, *"do not modify the face,
  pose, body position, skin, hair, or background in any way"* 같은 방어 문구가
  길게 붙어 있습니다 — 얼굴이 바뀌는 문제를 실제로 겪었다는 뜻입니다.
- **fill + 마스크**(hyeon-latest)는 **마스크 밖은 픽셀 그대로 남습니다.**
  얼굴이 바뀔 수가 없습니다. 대신 마스크를 잘못 잡으면 엉뚱한 데가 고쳐집니다.

**합칠 때 이 둘 중 하나를 골라야 합니다.** 양쪽을 다 남겨도 되지만,
그러면 사용자에게 "왜 옷 바꾸기가 두 개냐"를 설명해야 합니다.

`hyeon-version`의 **컬러웨이 4가지와 엠블럼 처리 선택**은 어느 쪽에도 없습니다 —
main의 "세기 3단계"보다 구체적이라 가져올 값이 있습니다.

## 4. 먼저 정해야 할 것

기능을 옮기기 전에 이것부터 정해야 합니다. **잘못 잡으면 옮긴 걸 다시 옮기게 됩니다.**

### 어느 구조로 갈 것인가

- **Next.js로 모으면** — 컴포넌트로 나뉘어 있어 여러 명이 동시에 작업하기 좋고,
  TypeScript가 실수를 잡아줍니다. 대신 단일 HTML 쪽 기능(브러시, 장소 사슬,
  접근 코드, 폴백)을 React로 다시 써야 합니다.
- **단일 HTML로 모으면** — 이미 배포되어 돌아가고 테스트 495개가 붙어 있습니다.
  대신 `main`의 React 컴포넌트와 Google Vision 연동을 옮겨와야 하고,
  파일 하나가 6,700줄이라 여럿이 동시에 고치기 어렵습니다.

발표까지 시간이 얼마 없다면 **이미 배포되어 돌아가는 쪽**을 바탕으로 잡는 편이
안전합니다. 시간이 있다면 Next.js가 나중까지 낫습니다.

### 순서

1. **바탕을 정한다** — 팀이 함께. 이 결정 없이 기능부터 옮기면 방향이 바뀔 때 전부 다시 해야 합니다.
2. **없어지면 안 되는 것부터 목록으로 만든다** — 위 비교표에서 한쪽에만 있는 항목. 옮기다 빠뜨리면 발표 당일에야 발견합니다.
3. **기능 하나 = 커밋 하나** — 통째로 붙여넣으면 어디서 깨졌는지 찾을 수 없습니다.
4. **옮길 때마다 테스트를 돌린다** — 양쪽 다 테스트가 있습니다.
5. **마지막에 배포하고 실제로 열어본다** — 로컬에서 되는 것과 배포판에서 되는 것은 다릅니다.

## 5. 옮길 때 주의할 것

### 백엔드 주소를 `localhost`로 두면 배포판이 죽습니다

`hyeon-version`에 `http://localhost:3001`이 **8군데** 있습니다. 배포하면 브라우저가
*방문자의 컴퓨터*를 부르게 되어 전부 실패합니다. 상대 경로(`/api/…`)여야 합니다.

### 서버리스에서는 포트를 열지 않습니다

버셀에서는 `app.listen`이 돌면 안 됩니다. Next.js는 이 문제가 없지만,
Express를 옮긴다면 `export default app`으로 내보내고 `VERCEL` 환경일 때
`listen`을 건너뛰어야 합니다.

### 보내는 이미지는 긴 변 1568px로

서버리스는 요청 본문을 4.5MB에서 자릅니다. 1200만 화소 사진은 base64로 5MB가
넘습니다. Claude Vision이 어차피 긴 변 1568px로 줄여서 보므로 잃는 것이 없습니다.

단, **스크린샷은 PNG를 유지**하세요. JPEG로 압축하면 작은 한글 UI 글자가 뭉개져
판독이 틀립니다(실측: "푸른숲" → "푸른솔").

### 등급 기준을 서버와 클라이언트가 다르게 쓰지 않게

한때 서버는 40점, 화면은 45점을 "중"의 기준으로 써서 40~44점 구간에서
배지와 게이지 색이 어긋났습니다. **기준은 한 곳에만** 두세요.

### 키와 아이 사진은 저장소에 넣지 마세요

키는 환경변수로, `.env.example`에는 구조만 둡니다. 아이 사진은 `.gitignore`에
파일명으로 못박혀 있습니다 — **한 번 커밋되면 히스토리에 영구히 남습니다.**

## 7. 확인 방법

### hyeon-latest

```bash
npm start                  # localhost:3001 — 프런트와 API가 같은 주소
node test/a11y.js          # DOCTYPE · viewport · 폰 실제 폭 · 낭독기
node test/gate.js          # 팀 접근 코드
node test/fallback.js      # API가 죽었을 때 점수 근거
node test/settle.js        # 결과 도착 시 화면이 밀리는지
npx vercel --prod          # 배포 (GitHub 연동 없이 CLI로)
```

`test/inpaint.js`는 로컬 백엔드가 떠 있어야 합니다.
파일명에 `live`·`holdout`이 들어간 것은 **실제 API를 불러 돈이 나갑니다.**

### main

```bash
npm run dev
npm test                   # vitest
```
