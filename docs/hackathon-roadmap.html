해커톤 고도화 로드맵

아이디어톤을 통과해 실제 해커톤으로 넘어갈 경우, 무엇부터 손댈지 정리했습니다. 새로 지어낸 목록이 아니라 심사 문답· AI 실무자 문답· 아이디어톤 문답 세 문서에서 이미 스스로 "인정할 것"으로 표시해둔 약점들을 실행 순서로 바꾼 것입니다. 카드마다 "지금 상태"와 "완료 기준"을 나눠서, 해커톤이 끝났을 때 뭘 보여주면 이 항목이 끝난 건지를 미리 정해뒀습니다.

최우선 이게 뚫리면 나머지가 다 무너지는 항목 근거 있음 기존 세 문서에 실측 근거로 이미 기록됨 저비용 해커톤 기간 내 완결 가능 중비용 부분 완결 또는 계정·자원 확보 필요 의존성 외부 의존·정책 제약으로 완결이 어려움

P0 · 근본 신뢰도

이 셋이 뚫리면 수익모델·확장성·법률을 아무리 잘 준비해도 "그래서 이 진단을 믿을 수 있냐"는 질문 하나로 전부 무너집니다. 해커톤 첫 주에 붙여야 하는 항목들입니다.

01

정확도 검증 표본 확대 + 오탐률 개선

최우선근거 있음

세 문서를 통틀어 가장 위험한 숫자입니다 — "98% 정확도"의 실체는 팀원이 직접 라벨링한 N=103장이고, 그중 안전한 사진 32장 중 19장(59%)을 오히려 위험하다고 오탐했습니다.

지금 상태 → 완료 기준
지금N=103, 자체 라벨, 오탐 59%
완료 기준제3자 라벨링 N≥300, 오탐률 30%대 이하, 배점 조정 근거 기록
근거 문서industry-qa.html #5
02

아동 얼굴 검출 정확도 실측

최우선근거 있음

지금 face-api.js 검출률(77~89%)은 전부 성인 얼굴 기준입니다. "아동 얼굴 데이터로는 한 번도 실측하지 못했다"고 스스로 인정한 상태 — 아이 전용 서비스인데 핵심 지표가 아이 데이터로 검증이 안 됐습니다.

지금 상태 → 완료 기준
지금성인 얼굴만 실측, 아동 데이터 실측 0건
완료 기준동의 기반·합성 아동 얼굴 테스트셋(최소 50장) 구축, 검출률 실측치 확보
근거 문서industry-qa.html #3
03

3단계 검증(재검증 루프) 구현

최우선근거 있음

README에 이미 "아직 없는 것"으로 명시된 기능입니다 — 보정된 사진을 다시 1단계 파이프라인에 통과시켜 위험이 실제로 사라졌는지 재확인하는 루프. "AI가 놓치면 책임은 누구인가"라는 질문에 대한 가장 실질적인 답이 될 기능입니다.

지금 상태 → 완료 기준
지금미구현 (수동 마스킹 UI도 미구현)
완료 기준보정 이미지 → 1단계 재통과 → 위험 해소 여부 자동 판정까지 동작
근거 문서README.md "아직 없는 것" · ideathon-qa.html #8

P1 · 이번에 나온 질문 검증

04

판정 비결정성 완화책 실제 구현

근거 있음저비용

같은 사진을 두 번 넣으면 판정이 6.8% 흔들린다는 것까지는 측정해뒀지만, 완화책(다수결 재실행 / "두 번 다 찾음·한 번만 찾음" UX 구분)은 둘 다 미구현입니다.

지금 상태 → 완료 기준
지금흔들림 측정만 됨, 완화책 미구현
완료 기준둘 중 하나 배포 후 재측정으로 흔들림 감소 확인
근거 문서industry-qa.html #6
05

프리미엄 전환율 실측 (수익모델 검증)

중비용저비용

수익모델 후보 ①(B2C 프리미엄)의 손익분기 계산에 쓴 "전환율 5%"는 근거 없는 가정값입니다. AI 배경교체 기능에 유료 안내 문구를 붙이고 결제 페이지 도달률을 재는 건 하루면 붙일 수 있는 가장 싼 검증입니다.

지금 상태 → 완료 기준
지금전환율 5% 가정, 실측 0건
완료 기준유료 안내 문구 배포 후 결제 페이지 도달률 실측치 확보
근거 문서ideathon-qa.html #6
06

모델 벤치마크 (Haiku vs 상위 모델)

근거 있음중비용

"충분히 싸고 빠른 모델을 먼저 골랐다"까지는 정직하게 인정했지만 실제 A/B 비교는 안 했습니다. 위험도 채점처럼 미묘한 판단이 필요한 항목에서 더 큰 모델이 오탐(01번)을 줄여줄 가능성이 있어 함께 봐야 합니다.

지금 상태 → 완료 기준
지금비교 없이 Haiku 4.5 단일 사용
완료 기준확장된 표본에 대해 상위 모델 1개 이상과 정확도·오탐률 비교표 확보
근거 문서industry-qa.html #1

P2 · 인프라 부채

"해커톤 데모 등급"이라고 스스로 인정한 부분들. 완벽한 프로덕션까지는 못 가도, 해커톤 기간에 충분히 따라잡을 수 있는 수준입니다.

07

충남대 게이트웨이 의존성 제거

의존성근거 있음

3단계 교차검증이 월 5,000 크레딧짜리 학생 계정에 걸려 있어, "구조는 증명됐지만 상용 등급이 아니다"라는 게 이미 인정된 상태입니다.

지금 상태 → 완료 기준
지금충남대 학생 계정(비상용) 의존
완료 기준정식 Gemini API(또는 동급) 키로 교차검증 경로 이전

08

접근 인증 강화 + 프론트 구조 정리

의존성중비용

접근 코드 "qwerty"와 빌드 없는 단일 HTML은 "빠르게 만들고 정직하게 배포"라는 해커톤 목표에는 맞았지만, 다음 단계에서는 손봐야 할 부채로 이미 목록화돼 있습니다.

지금 상태 → 완료 기준
지금고정 접근 코드, 코드 분할·CSP 없음
완료 기준최소 인증(로그인 또는 강화된 코드) + 1차 코드 분할 적용
근거 문서industry-qa.html #10

P3 · 관계·포지셔닝

코드가 아니라 "시도한 흔적"이 필요한 항목들. 계약이나 완결까지는 못 가도, 접촉 기록 하나만 있어도 "포지셔닝 문장"에서 "실제로 시도한 확장"으로 격이 달라집니다.

09

지자체·교육청 접촉 시작 (B2G 검증)

의존성저비용

"지우개서비스=사후구제 / 우리=사전예방" 포지셔닝은 있지만 실제 접촉은 없었다고 이미 인정한 부분입니다.

지금 상태 → 완료 기준
지금접촉 이력 0건, 포지셔닝 문장만 존재
완료 기준최소 1개 기관 담당 부서에 문의 기록(메일·통화) 확보

법률 자문 착수

이 로드맵을 쓰는 법

  • P0 세 개를 먼저 끝내지 않은 채 P1~P3로 넘어가지 마세요. 정확도·오탐·아동 얼굴 검증이 안 뚫린 상태로 확장성·비즈니스 얘기를 하면, 심사에서 "그래서 진단을 믿을 수 있냐"는 질문 한 방에 나머지 준비가 전부 무의미해집니다.
  • 완료 기준은 "완벽"이 아니라 "실측치 확보"입니다. 예를 들어 01번은 오탐률을 0%로 만드는 게 목표가 아니라, 표본을 키우고 그 결과를 정직하게 보고할 수 있는 상태를 목표로 합니다 — 이 프로젝트 전체가 지금까지 그렇게 움직여왔습니다.
  • P3는 "완결"이 아니라 "시도"가 기준입니다. 지자체 계약이나 법률 자문 완료를 해커톤 기간에 끝낼 순 없습니다. 접촉했다는 기록 하나가 포지셔닝 문장을 실제 시도로 바꿔줍니다.
