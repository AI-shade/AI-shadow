아이디어톤 관계자 문답

심사 문답(qa.html)이 배점표, AI 실무자 문답이 엔지니어링 트레이드오프를 캐묻는다면, 이 문서는 "이 문제가 진짜 문제인가, 이 해법이 왜 특별한가, 세상에 나가면 무슨 일이 생기는가"를 묻는 아이디어톤 관계자 질문 10개를 모았습니다. 코드 품질보다 문제 실재성, 차별화, 비즈니스·확장 가능성, 사회적 리스크를 봅니다. 근거가 있는 답은 출처를 그대로 달았고, 근거가 없는 곳은 인정으로 정직하게 표시했습니다 — 조사 안 한 걸 조사한 것처럼 말하지 않습니다.

숫자 실측·인용 근거로 답할 수 있음 화면 그 자리에서 눌러 보여줄 수 있음 인정 솔직히 근거가 없거나 한계를 인정해야 함 추정 실측 아님 — 어림 계산·논리적 가정임을 밝힘 중요 아이디어톤 관계자가 가장 날카롭게 파고들 질문

문제의 실재성

01

"셰어런팅"이 실제로 얼마나 심각한 문제인지, 근거가 있나요?

중요숫자인정

이제 국내 근거도 있습니다. 세이브더칠드런 조사(2021, 만 0~11세 자녀 부모 1,000명) — 86.1%가 SNS에 자녀 사진을 올렸고, 그중 동의를 구한 경우는 44.6%뿐이며 13.2%는 게시 후 부정적 경험(낯선 사람 접근 등)을 겪었다고 답했습니다. 인천 지역 약취·유인 범죄는 2021년 16건에서 2024년 29건으로 4년 연속 증가했고, 같은 지역 학부모가 "아동 접근·유괴미수 사건이 잇따르자 딸의 SNS 사진을 직접 지웠다"는 실제 사례 (2025.9)도 언론에 보도됐습니다. 해외 근거도 병행합니다 — 호주 정부 eSafety Commissioner 공식 발표(2026.7.28, 학교 SNS에서 수집된 이미지로 교사·학생 딥페이크 신고 100건 이상)와 바클레이즈(영국) 분석(향후 10년 아동 신원도용 범죄의 3분의 2가 셰어런팅에서 비롯).

국내 근거 — 원문 확인
인천 약취·유인 범죄 추이2021년 16건 → 2022년 18건 → 2023년 23건 → 2024년 29건
지우개서비스 처리 실적2023.4~2024.4 누적 16,518건 처리(신청 17,148건)
국회 계류 법안2026.1.22 발의 — 미성년자 잊힐 권리·제3자 게시물 삭제 입증책임 전환(정보통신망법·개인정보보호법 개정안)
인정할 것 다만 두 가지는 여전히 얇습니다. ① 인과관계 — 인천의 약취·유인 범죄 증가와 SNS 셰어런팅을 직접 연결한 공식 통계나 연구는 없습니다(둘 다 사실이지만, "SNS에 올려서 늘었다"는 인과는 검증된 적 없습니다). ② 실제 사건은 아직 사례 기반(N=2~3)입니다 — 인천 학부모 사례는 실제 범죄 피해가 아니라 불안감으로 인한 예방적 삭제이고, 자주 인용되는 "2021년 10월 SNS 정보로 9세 여아 유괴" 건은 원출처를 추적한 결과 중앙일보·개인정보보호위원회 공동기획 (2022.7.8) 기사임을 확인했지만, 그 기사 자체도 법원명·사건번호·선고일 없는 한 문장 요약이라 "판결로 확정된 사실"처럼 말하면 안 되고, 인용할 땐 반드시 이 출처를 함께 표기해야 합니다(미성년 피해자 사건은 신원 비공개가 원칙이라 판결문 자체가 없을 가능성이 높습니다). 홍성 여고생 사망 사건(2025.9, 무인점포 CCTV 유포로 신원 특정 후 사망)은 국내에서 아동 이미지 무단 확산이 실제로 얼마나 치명적일 수 있는지 보여주는 강력한 사례지만, 부모가 SNS에 올린 게 아니라 제3자가 유포한 사건이라 "셰어런팅"의 예로 그대로 쓰면 사실관계가 틀립니다 — "아동 이미지 노출의 파급력" 일반을 말할 때만 구분해서 인용해야 합니다.
02

"사진 한 장이 아니라 쌓이는 정보가 위험하다"는 인사이트는 실제로 구현됐나요, 발표용 훅인가요?

화면숫자인정

실제로 구현돼 있습니다 — 개발 기록 11번 섹션("스케줄 패턴 분석 — 핵심 차별점 구현")에 따르면, 처음엔 업로드한 과거 게시물 스크린샷 개수만 세던 목업이었다가 실제 Claude API 연동으로 교체되어 요일·시간대·장소 반복 패턴을 탐지합니다. 스크린샷 4장을 포함하면 전체 진단 시간이 약 17초로 늘어나는 것까지 실측돼 있습니다.

인정할 것 — 과장하기 쉬운 지점 "쌓이는 정보를 자동으로 추적한다"고 말하면 과장입니다. 정확히는 사용자가 자신의 과거 게시물을 직접 스크린샷 찍어 업로드해야 작동합니다. Instagram Basic Display API가 2024년 12월 폐지돼 개인 계정을 자동 연동할 경로가 없고, 웹 스크래핑은 약관 위반 소지가 있어 의도적으로 하지 않기로 했습니다(기획서에 명시). 즉 "SNS 계정을 연결하면 알아서 위험을 추적"이 아니라 "사용자가 제공한 과거 기록을 분석해준다"는 게 정확한 설명입니다.

차별화·경쟁 지형

03

기존에 이미 있는 솔루션과 뭐가 다른가요?

중요숫자

경쟁 지형을 네 유형으로 정리해뒀습니다. A. 블러 앱(PrivacyBlur, BlurMe 등) — 얼굴만 자동으로 가리고, 무엇이 위험한지 판단은 사람 몫. B. 메타데이터 분석기(AI Metadata Cleaner 등) — EXIF·GPS만 지우고 사진 내용 자체는 안 봄. C. 지오로케이션 AI(GeoSpy) — 사진만으로 촬영 위치를 추정하는 공격 도구이며 방어 기능이 없음. D. 정부 사후 구제 (개인정보보호위원회 지우개서비스) — 이미 올라간 게시물만 삭제, 예방 기능 없음.

차별점 셋: ① 맥락 판단 — 원복·명찰·엠블럼·학원차량처럼 "이것으로 기관을 특정할 수 있는가"를 의미 단위로 읽고, 동시에 오탐을 줄이는 "보고하지 말 것" 목록(체크무늬 치마, 별무늬 양말 등)도 명시. ② 누적 패턴 분석(위 2번 참고) — 단일 사진만 보는 도구는 원리적으로 불가능한 영역. ③ 블러가 아니라 보정 — 위험 요소만 자연스럽게 지워 "그래도 올릴 수 있는 사진"으로 만듦.

포지셔닝 한 문장 지우개서비스가 "이미 올라간 것을 지우는" 사후 구제라면, 이 서비스는 "올리기 전에 막는" 사전 예방.
인정할 것 이 비교는 팀이 직접 조사한 것이며, 특허 조사나 전수 시장 스캔 같은 정식 실사는 아닙니다. 경쟁 유형 4가지 밖에 더 있을 다른 접근(예: 플랫폼 자체의 자동 블러 기능)은 조사 범위에 없었습니다.
04

"블러 대신 보정"이 실사용률을 높인다는 근거가 있나요?

인정

지금은 논리적 추론입니다 — "블러 처리한 사진은 보기 싫어서 결국 안 올리게 되고, 안 올리면 도구 자체를 계속 쓰지 않는다"는 가설이며, 여기서 "보정 쪽이 계속 쓰인다"는 결론을 끌어냈습니다.

인정할 것 블러 버전과 보정 버전을 같은 사용자에게 나눠 주고 실제 게시 여부·재사용률을 비교한 A/B 테스트나 설문은 하지 않았습니다. 방향은 합리적이지만 실측된 사실이 아니라 가정입니다.

타겟·비즈니스·확장성

05

타겟 고객은 정확히 누구인가요? "부모" 전체인가요?

숫자인정

잠재 시장 크기의 근거로는 세이브더칠드런 조사 대상(만 0~11세 자녀를 둔 부모, 최근 3개월 내 SNS 게시 경험자, N=1,000, 그중 86.1%가 게시 경험자)을 인용할 수 있습니다.

인정할 것 이 안에서 어떤 세그먼트(SNS 활동이 잦은 인플루언서형 부모, 초보 부모, 어린이집·학원처럼 학부모 동의 없이 아동 사진을 올리는 기관 계정 운영자)를 먼저 공략할지에 대한 우선순위나 근거는 아직 없습니다. "부모"로 뭉뚱그려진 상태입니다.
06

수익모델은 무엇인가요? 이 서비스는 지속가능한가요?

중요숫자추정인정

확정된 모델은 없지만, 원가 구조에서 출발해 4가지 후보를 검토해뒀습니다. ① B2C 프리미엄 — 위험도 진단·기본 보정은 무료로 두고, 실비가 드는 fal.ai AI 배경교체만 유료화. 이미 코드에서 이 기능이 "유료·원본전송 동의 필요"로 분리돼 있어 과금 경계선을 새로 설계할 필요가 없다는 게 강점입니다. ② B2G 공공위탁 — 지자체·교육청이 비용을 대고 부모·기관에는 무료 제공. "지우개서비스가 사후 구제라면 우리는 사전 예방"이라는 기존 포지셔닝, 그리고 이해민 의원 개정안이 국회에 계류 중이라는 정책 모멘텀이 명분이 됩니다. ③ B2B2C 기관 라이선스 — 원복·현수막이 반복 노출되는 어린이집·학원 대상. ④ API 화이트라벨 — 이미 사용자가 있는 알림장 앱에 진단 API를 붙이고 호출당 과금.

07

아이 사진에만 국한되나요, 아니면 더 큰 문제로 확장 가능한가요?

중요숫자인정

4갈래를 검토했고, 근거의 무게가 다릅니다. ① 도메인 일반화 — 지금 파이프라인 (얼굴 마스킹→OCR→위험도 채점→AI 보정)은 사실 "아이 전용"이 아니라 "사진 속 개인 식별 단서를 읽는" 범용 구조입니다. 노인·치매환자 돌봄시설, 스토킹 피해자의 위치 노출 방지, 빈집털이로 이어지는 "부재중 인증샷"에도 그대로 적용됩니다. ② 연령 확장 — 0~11세(부모가 대신 올림)에서 12~18세(본인이 직접 올림)로. 이해민 의원 개정안이 보호 범위를 미성년자 전체로 넓히는 것과 같은 방향입니다. ③ 콘텐츠 유형 확장 — 사진에서 영상(키즈 유튜브· 숏폼)으로. 유튜브 키즈 채널 상위 8개 구독자만 1,000만 명 이상이라는 시장 통계가 있습니다. ④ 시점 확장 — 게시 전 진단에서 이미 올라간 과거 게시물 전체 스캔으로. 지우개서비스와의 차별화가 더 선명해집니다.

③ 사진→영상근거 중간(시장 통계 존재) · 난이도 높음(기술 스택 자체가 다름)
④ 시점 확장(전수 스캔)근거 약함 · 난이도 막힘(SNS API 폐지로 자동 연동 불가)
인정할 것 가장 방어 가능한 건 ①입니다 — "아이"는 UX 카피와 첫 타겟 시장의 선택이지, 코드가 아이 얼굴에만 반응하도록 짜여 있는 게 아니라는 건 README에 있는 실제 아키텍처 사실입니다. 반면 ②·③·④는 지자체·교육청은 물론 어떤 확장 대상과도 실제 접촉이나 수요 확인을 한 적이 없습니다 — ③은 지금 아키텍처로 못 만들고, ④는 Instagram Basic Display API 폐지로 자동 연동 경로 자체가 막혀 있어 "말이 되는 방향"이 아니라 "막힌 방향"에 더 가깝습니다.

사회적 책임

08

AI가 위험을 놓쳤는데 부모가 그걸 믿고 올렸다면, 책임은 누구에게 있나요?

중요숫자

실측 수치로 먼저 답합니다 — 팀이 손으로 분류한 정답표 103장 기준, "놓쳐서는 안 되는 사진" 71장 중 4장을 놓쳤고, 안전한 사진 32장 중 19장을 오히려 위험하다고 오탐했습니다. 그래서 설계 원칙을 "실패하면 열어준다"가 아니라 "실패하면 멈추고 사용자에게 묻는다"로 잡았습니다 — 얼굴 검출이 실패하면 자동 전송을 멈추고 사용자가 직접 선택하게 하는 안전장치가 실제로 붙어 있습니다.

인정할 것 이 안전장치는 "검출 실패" 케이스를 막아줄 뿐, 위험도 진단이 놓친 4장처럼 "검출은 됐지만 판단이 틀린" 경우까지 막아주지는 않습니다. 이 경우 사용자가 "AI가 안전하다고 했으니 괜찮겠지"라고 오판할 가능성이 구조적으로 남아 있고, 이걸 "참고용 진단이지 보증이 아니다"라는 문구로 얼마나 명확히 관리하고 있는지는 별도로 점검이 필요합니다.
09

법적·제도적 측면은 검토했나요? (아동 개인정보보호법, 초상권)

인정

개인정보보호위원회가 셰어런팅을 "보호자에 의한 개인정보 침해"로 규정하고 지우개서비스를 운영 중이라는 사실은 인지하고 있고, 이 서비스를 그와 다른 위치(사전 예방)로 포지셔닝했습니다.

인정할 것 벤더별 API 이용약관을 읽은 수준의 확인이었지, 서명된 법률 검토나 아동 개인정보보호법상 특례 조항에 대한 정식 자문을 거친 것은 아닙니다. 아동 대상 서비스가 실제로 운영에 들어가려면 이 부분은 반드시 별도로 짚어야 할 과제로 남아 있습니다.

근본 질문

10

발표 오프닝의 임팩트 통계(딥페이크 신고 2배, 신원도용 범죄 3분의 2)와 실제 제품의 스케일 사이에 괴리가 있지 않나요?

중요인정

정직하게, 있습니다. 지금은 사진 한 장을 진단·보정해주는 개인용 웹 도구 단계이고, 오프닝 통계는 문제의 "존재와 심각성"을 입증하는 근거이지 이 제품이 이미 그 규모의 문제를 해결하고 있다는 근거는 아닙니다.

인정할 것 이 격차는 팀도 알고 있고, 그래서 7번 질문의 확장 방향(개인용 도구 → 지자체·교육청 연계 공공 서비스)이 존재합니다. 다만 그 경로는 아직 포지셔닝 문장 수준이며, "지금 이 프로토타입이 호주 사례 수준의 문제를 막는다"고 말하면 과장입니다. 정확한 표현은 "이 문제의 크기를 확인했고, 그 크기에 맞는 인프라로 가는 첫 단계를 만들었다"입니다.
