# 폰 화면을 어플 배치로 바꾸기 — 설계

아이SHADOW · Campus AX-Ton

## 1. 배경

사용자 제보 둘에서 출발한다.

> "핸드폰 어플용 목업을 손봐야할거같아 너무 조잡해"
> "한 화면에 글이 너무많아"

실제로 재보니 근거가 있었다 (폰 390×844 기준).

| 화면 | 글자 | 높이 | 폰 화면 |
|---|---|---|---|
| `screen-form` | 122자 | 591px | 0.7개분 |
| **`screen-correct`** | **517자** | **1658px** | **2.0개분** |
| `screen-verify` | 127자 | 457px | 0.5개분 |

`screen-correct`의 「옷 손보기」 카드 하나가 설명만 108자에 높이 335px로, **카드 한 장이
폰 화면의 40%**를 먹는다. 여기에 진단 결과의 항목별 근거 산문 5개(60~85자씩, 합 300자
이상)가 더해진다.

기준 삼을 배치는 사용자가 준 `어플ver.jpg`다. 거기서 가져오는 골격은 넷이다.

1. 하단 탭바 5칸 (가운데 원형 강조 버튼)
2. 결론을 크게 말하는 히어로 카드
3. 정보를 작은 카드로 쪼개고, 카드마다 접기
4. 글 대신 숫자·막대·칩

시안은 `scratchpad/sian.html`로 만들어 확인을 받았다. 그 시안 기준 실측:

```
진단 결과   본문 667px / 화면 667px   넘침 0     (지금은 2개분 스크롤)
보정        넘침 0                              (지금은 2.0개분)
알아보기    넘침 7px                            (사실상 한 화면)
```

## 2. 범위

### 하는 것

- **폰 폭에서만** 하단 탭바가 있는 어플 배치로 바꾼다.
- 진단·보정·검증 세 화면의 안쪽 구성을 히어로 카드 + 작은 카드 + 접기로 다시 짠다.
- 핀 고정 섹션 세 개(`#steps`, `#features`, `#why`)를 「알아보기」 탭에서 카드 목록으로
  보여주고, `#faq`를 「문답」 탭으로, `#pattern-check`를 「과거글」 탭으로 배정한다.

### 안 하는 것 (YAGNI)

- **데스크톱은 건드리지 않는다.** 긴 스크롤 페이지와 핀 고정 연출을 그대로 둔다.
- **DOM을 옮기지 않는다.** 아래 5절 참고.
- 새 색을 만들지 않는다. `--accent-bar` 하나만 추가한다 (6절).
- 근거 산문을 지우거나 짧게 고쳐 쓰지 않는다. **접기만 한다** (4.2절).
- 아이콘을 새로 그리지 않는다. 앱에 이미 있는 `mono-icon` SVG를 쓴다.

### 경계가 왜 여기인가

`test/pinned.js` 머리말이 이렇게 적고 있다.

> 좁은 화면 / 모션 축소: 붙이지 않고 전부 펼친다

즉 **폰 폭에서는 핀 고정이 애초에 안 걸린다.** 그래서 폰에서 이 섹션들을 카드 목록으로
보여주는 것은 핀 고정 동작과 충돌하지 않는다. 데스크톱을 그대로 두는 한 `pinned.js`
45개는 손댈 일이 없다.

## 3. 탭 구조

```
┌──────┬────────┬─────┬──────────┬──────┐
│ 진단 │ 과거글 │  ＋ │ 알아보기 │ 문답 │
└──────┴────────┴─────┴──────────┴──────┘
```

| 탭 | 담는 것 | 현재 무엇이었나 |
|---|---|---|
| 진단 | 도구 3단계 (진단 → 보정 → 검증) | `main#tool` |
| 과거글 | 과거 게시물 스크린샷 패턴 검사 | `#pattern-check`, `#screen-pattern` |
| **＋** | 어디서든 「사진 넣기」로 진단 시작 | (없던 것) |
| 알아보기 | 세 단계 · 무엇을 찾아내나 · 아이를 건드리지 않는 원칙 | `#steps` + `#features` + `#why` |
| 문답 | 자주 묻는 질문 | `#faq` |

`＋`는 새로 만드는 유일한 진입점이다. 레퍼런스의 가운데 원형 버튼 자리를 그대로 쓴다.
누르면 `#photoInput`을 열고, 파일이 선택되면 「진단」 탭으로 이동한다.

**탭 상태는 주소에 남긴다** (`#tool`, `#pattern-check`, …). 이미 앵커가 있고
`scroll-margin-top: 5rem`도 걸려 있어, 데스크톱에서 같은 주소가 그대로 동작한다.
새로고침 시 앵커를 떼는 기존 처리(`performance.getEntriesByType('navigation')`)는
그대로 둔다.

## 4. 화면 설계

### 4.1 진단 결과

```
┌─────────────────────────────┐
│ 진단 결과            ●○○    │  앱바 + 단계 점
├─────────────────────────────┤
│ ███ 60 / 100        [ 중 ]  │  히어로 (다크 카드)
│ ███ 교복과 캡션이 만나면서   │
│ ███ 학교·요일·시간이 …       │
├─────────────────────────────┤
│ 무엇이 걸렸나   근거 펼치기⌄ │
│  소속 노출   [왜?]   22 / 22 │
│  ▬▬▬▬▬▬▬▬▬▬▬▬▬▬▬▬▬ (빨강)   │
│  캡션 노출   [왜?]   18 / 18 │
│  …                          │
├─────────────────────────────┤
│ 지금 할 일                   │
│  ① 가슴 마크와 교복 색을 …   │
│  ② 캡션에서 학교명·요일 …    │
├─────────────────────────────┤
│      [ 보정하러 가기 ]       │  하단 고정 액션
├──────┬──────┬───┬──────┬────┤
│ 진단 │과거글│ ＋│알아보기│문답│
└──────┴──────┴───┴──────┴────┘
```

- **히어로는 화면당 하나뿐인 다크 카드**다 (가이드라인 5절).

- **폰에서는 오각형 그래프를 뺀다.** 이건 눈에 띄는 결정이라 따로 적어둔다.

  - 오각형은 항목 다섯 개를 한눈에 보여주려고 있는 것인데, 바로 아래 막대 다섯 개가
    같은 정보를 **더 정확하게** 준다. 오각형에서는 `22/22`와 `18/18`의 차이를 눈으로
    못 읽지만 막대와 숫자로는 읽힌다.
  - 자리를 많이 먹는다. 시안의 넘침 0은 오각형이 없는 상태에서 잰 값이다. 도로 넣으면
    한 화면에 안 들어간다.
  - AGENTS.md 5절이 이미 "점수 숫자가 오각형 선과 겹친다(낮은 점수일 때)"를 알려진
    구멍으로 적고 있다. 폰의 좁은 폭에서 더 심해진다.

  **데스크톱에서는 오각형을 그대로 둔다.** GSAP "오각형 그려지기" 모션도 그대로다.

  **발표자료 처리 — 확정.** 4번 슬라이드(오각형이 있는 진단 결과 화면)는 **데스크톱 폭으로
  찍는다.** 폰에 오각형을 도로 넣어 자리를 쥐어짜지 않는다. 나머지 슬라이드는 폰 폭 그대로다.

  즉 발표자료의 폰 목업 안에 **한 장만 데스크톱 화면**이 들어간다. 목업 틀이 폰인데 안이
  데스크톱이면 어색하므로, 4번 슬라이드는 **폰 목업을 쓰지 않고** 화면을 그대로 크게
  얹는다 — "같은 앱의 큰 화면"으로 읽히게 한다. 슬라이드별 촬영 폭은 10절 표에 있다.
- 만점 항목의 막대는 `--risk-high`로 칠한다. **글을 안 읽어도 어디가 터졌는지 보인다.**
- 0점 항목의 막대는 `--line-strong`으로 아주 짧게 남긴다(폭 2%). 빈 줄로 두면 "검사를
  안 한 것"으로 읽힌다.

### 4.2 근거 접기 — 지키는 선

근거 산문은 **지우지 않는다.** AGENTS.md가 "총점이 아니라 항목별로 받는 이유는 근거를
댈 수 있어야 하기 때문"이라고 못박고 있다.

- 항상 보이는 것: **항목 이름 · 점수 · 막대**
- 접히는 것: **근거 산문뿐**
- 접는 단추는 진짜 `<button>` + `aria-expanded`. `<div onclick>`으로 만들지 않는다.
- **JS가 죽으면 펼쳐진 상태로 남는다.** 접기는 JS가 클래스를 붙여야 시작된다
  (`.reveal`과 같은 방식). 스크립트가 실패해도 글이 사라지지 않는다.

> 주의: 예전에 *"근거 자리가 눌러야 하거나 기다려야 하는 것으로 읽힌다"*는 실사용
> 제보가 있었고 `test/a11y.js`가 그 자리를 검사한다. 그래서 접힌 상태에서도 점수와
> 막대는 **채워진 채로** 보여야 하고, 「왜?」는 근거를 여는 단추이지 결과를 기다리는
> 표시가 아니어야 한다.

### 4.3 보정

```
┌─────────────────────────────┐
│ 보정                 ○●○    │
├─────────────────────────────┤
│  원본        │   처리 후     │  결과를 맨 위로
│  [사진]      │   [사진]      │
├─────────────────────────────┤
│ 어떻게 고칠까요     자세히⌄ │
│ ┌─────────┐ ┌─────────┐    │
│ │배경 흐림 │ │자연스럽게│    │  2×2 타일
│ └─────────┘ └─────────┘    │
│ ┌─────────┐ ┌─────────┐    │
│ │⚠옷 손보기│ │⚠AI 배경 │    │  원본 전송 둘을 아래 줄에
│ └─────────┘ └─────────┘    │
├─────────────────────────────┤
│ 옷 색     [칩][칩][칩][칩]   │
│ 교복 티   [칩][칩][칩][칩]   │
├─────────────────────────────┤
│    [ 완료 → 검증하기 ]       │
└─────────────────────────────┘
```

- 레퍼런스가 결과를 항상 위에 두는 것을 따른다. 지금은 미리보기가 방식 목록 아래에 있어
  폰에서 한 화면에 같이 안 보인다.
- 방식 설명은 **첫 줄만** 보이고 나머지는 「자세히」로 접는다. 카드 335px → 약 120px.
- `⚠ 원본 전송` 두 방식을 아래 줄에 나란히 두어 같은 종류임이 한눈에 들어오게 한다
  (이미 마크업 주석에 같은 의도가 적혀 있다).
- 옷 색·교복 티는 칩 줄로 내린다. `flex-wrap: wrap` + `white-space: nowrap`은 이미
  적용돼 있고 `test/pill-wrap.js`가 지킨다.

### 4.4 검증 · 과거글 · 알아보기 · 문답

- **검증**: 지금도 0.5개분이라 배치를 크게 바꾸지 않는다. 도장·태그를 히어로 자리로
  올리고, 긴 설명 산문만 접는다.
- **과거글**: `#pattern-check` 폼과 `#screen-pattern` 결과를 한 탭에 둔다.
- **알아보기**: 세 섹션을 카드 세 개로. 각 카드는 항목 목록이고, 항목을 누르면 펼친다.
- **문답**: `#faq`의 쌓기 방식을 폰에서는 단순 아코디언으로 둔다.

## 5. 구현 방식

**DOM을 옮기지 않는다.** 자바스크립트로 섹션을 다른 부모에 이사시키면 리사이즈마다
되돌려야 하고, `position: sticky`와 GSAP ScrollTrigger가 꼬인다. 노트에 ScrollSmoother로
sticky를 전부 깨뜨린 사고 기록이 있다 — 같은 실수를 반복하지 않는다.

대신:

1. 섹션들은 지금 자리에 그대로 둔다.
2. 폰 폭에서 **비활성 탭에 해당하는 섹션을 CSS로 숨긴다** (`display: none`).
3. 탭바는 `position: fixed; bottom: 0`으로 띄우고, `body`에 탭바 높이만큼 아래 여백을 준다.
4. 탭 전환은 `<html>`에 `data-tab="진단|과거글|알아보기|문답"`을 세우는 것으로 끝낸다.
   CSS가 나머지를 한다.

```css
@media (max-width: 560px) {
  .app-tabbar { display: flex; }               /* 데스크톱에선 없음 */
  :root[data-tab="알아보기"] main#tool { display: none; }
  /* … 탭별로 보일 것만 남긴다 */
}
```

**JS가 죽어도 쓸 수 있어야 한다.** `data-tab`이 없으면 아무것도 숨기지 않는다 —
지금처럼 전부 이어진 한 페이지가 된다. 탭바는 진짜 `<a href="#tool">` 링크라서
JS 없이도 해당 자리로 이동한다.

## 6. 색

새 팔레트를 만들지 않는다. `:root`에 토큰 **하나만** 추가한다.

```css
--accent-bar: #f4d95c;   /* 하단 액션 바 + 가운데 원형 버튼 전용 */
```

본문 골드(`--accent: #f0cb00`)보다 연하다. 이유는 두 가지다.

1. 사용자 요청 — "하단 바 노란색 좀만 연한색으로".
2. 점수 막대·단계 표시에 쓰는 골드와 **다음 동작**을 구분한다.

실측 대비:

| | 색 | 먹색 글씨 | 흰 배경과 |
|---|---|---|---|
| 본문 골드 | `#f0cb00` | 10.98:1 | 1.59:1 |
| **하단 바** | **`#f4d95c`** | **12.37:1** | **1.41:1** |

더 연한 후보(`#f8e690`, `#fbf1c4`)는 흰 배경과의 대비가 1.26 / 1.14까지 떨어져 버튼
형태가 사라진다. 화면에서 가장 중요한 동작이므로 여기서 멈춘다.

`--accent`(브랜드 골드, UNC Charlotte 색상 가이드에서 온 값)는 **바꾸지 않는다.**

## 7. 접근성

- 탭바는 `role="tablist"`, 각 탭은 `role="tab"` + `aria-selected`. 탭 패널은
  `aria-labelledby`로 연결한다.
- 접기 단추는 `<button aria-expanded>`. 펼침 상태가 낭독기에 읽혀야 한다.
- 하단 고정 바와 탭바가 본문을 가리지 않도록 `body`에 아래 여백을 준다. 폼 입력에
  초점이 갈 때 가려지는지 확인한다.
- `prefers-reduced-motion`에서 탭 전환 애니메이션을 끈다.
- 대비는 6절 실측값을 따른다.

## 9. 위험과 되돌리기

| 위험 | 대비 |
|---|---|
| 탭 전환이 sticky·GSAP와 충돌 | DOM을 안 옮기고 CSS `display`만 쓴다. 데스크톱에는 규칙이 적용되지 않는다 |
| 접기 때문에 근거를 못 찾음 | 점수·막대는 항상 보인다. JS 실패 시 펼쳐진 상태 |
| 하단 고정 바가 입력칸을 가림 | `body` 아래 여백 + 초점 이동 검사 |
| 폰 폭 경계(560px)에서 어정쩡 | 경계 근처 폭(390·430·560·600)에서 `phone-fit.js`가 잰다 |

되돌리기는 커밋 단위로 한다. 탭바 도입 / 진단 화면 / 보정 화면 / 접기를 각각 따로
커밋해서, 한 덩어리만 되돌릴 수 있게 한다.
