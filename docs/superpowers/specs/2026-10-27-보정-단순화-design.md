# 보정 화면 단순화 + 배경 교체를 마스크 방식으로 — 설계

2026-10-27 · 출발점: `옷바꾸기 버그 보고서.pdf` (팀 제보)

> "왼쪽 사진을 배경변경했는데 지 맘대로 옷도바꾸고 사진 방향이 바꼇다고 인식을 못하고
> 배경도 세로기준로 바꿔버렸어 이상하게"
> "좀 더 간단하게 1. 배경만 바꾸기 2. 옷 교체하기"

## 잰 것

| 무엇 | 결과 |
|---|---|
| 예시 사진 2장을 90° 돌렸을 때 얼굴 검출 | 태권도복: 진짜 얼굴은 놓치고 문의 로고를 얼굴로 잡음 · 원복: 0명 |
| 같은 때 인물 분리 | 몸통은 잡지만 다리 끝·바지 일부를 놓침 |
| → 보고서 증상 | 상체(패딩·얼굴)는 원본으로 되돌아왔고, 놓친 다리에 AI가 그린 청바지가 남음 |
| 얼굴 검출로 방향 자동 판단 (사진 25장 × 4방향) | 신뢰도 합 기준 18/25, 최고 신뢰도 기준 20/25만 바른 방향을 고름 — 5장 중 1장꼴로 멀쩡한 사진을 눕힘 → **자동 판단 안 함** |

## 바꾸는 것

### 1. 사진 돌리기 (사용자가 직접)

- 업로드 미리보기 아래에 `↻ 사진 돌리기` 버튼. 누를 때마다 시계방향 90°. 브라우저 안에서 처리.
- 돌린 사진이 `uploadedPhotoUrl`이 되어 진단·보정 전부에 쓰인다.
- EXIF 좌표는 **원본 파일 URL**(`originalPhotoUrl`)에서 읽는다 — 캔버스를 거치면 EXIF가 사라진다.
- 얼굴을 못 찾았을 때 뜨는 창(`noFaceConsentModal`)에 "사진이 누워 있다면 돌린 뒤 다시 진단해보세요" 한 줄.
- AI가 방향을 판단하지 않는다(위 측정).

### 2. 보정 카드 2개

```
[ 배경 교체 ]  [ 옷 교체 ]     ⚠ 둘 다 원본 전송 · AI
```

- 빠짐: 배경 흐림, 자연스럽게 덮기, 옷 색 5종, 마크 포켓/지우기, 색만 바꾸기(로컬).
- 화면에 들어와도 **자동으로 아무것도 실행하지 않는다** — 두 방식 모두 돈이 들고 원본이 나간다.
  미리보기는 원본, 안내는 "바꿀 것을 골라주세요".
- 처리 방식 추천 호출(`/api/recommend-correction`)을 부르지 않는다 — 고를 것이 없다.
- 찾은 글자 목록(`targetPicker`)·덮기 도구(`coverTools`)·간판 AI(`signAiRow`)는 숨긴다.
- 동의 거절 → 선택 해제, 미리보기 원본, "보정 없이 그대로 저장할 수 있어요".
- 적용하기로 두 단계를 쌓는 흐름(배경 → 옷)은 그대로.

### 3. 배경 교체 = `flux-pro/v1/fill` + 사람 마스크

- 마스크: 흰색 = 사람 바깥 전부. **검정(보존)** = 인물 분리 결과를 넓힌 것 + 얼굴 상자 + 손 상자.
  얼굴·손을 검게 덮는 것이 마지막 단계(AGENTS.md 1절).
- 인물 분리 실패(null) → 실행하지 않고 "사람을 찾지 못했어요". kontext로 돌아가지 않는다.
- 보내는 크기: 긴 변 **1024px**(옷 교체는 지금처럼 1568). AI 결과는 마스크 안쪽(배경)에만 합성 —
  사람은 원본 해상도 그대로.
- 프롬프트: Claude가 사진을 보고 구체적인 일반 장소를 정한다(지금 kontext용 지시의 배경 부분 유지).
  추가: 글자·간판·로고·사람이 새로 생기지 않게.
- 서버 `/api/replace-background`가 `maskBase64`를 받아 fill을 부른다. kontext 호출은 지운다.
- kontext 전용 후처리(환각 인물 제거, 얼굴 어긋남 정렬, 원본 인물 덮어쓰기)는 이 경로에서 빠진다 —
  fill은 마스크 바깥을 바꾸지 않는다(2026-08-21 실측).
- 비용 1회 약 $0.04(1024×768) — 지금 kontext와 비슷.

### 4. 옷 교체 = 옷 전체 하나

- 늘 `runOutfitSwap(…, emblemMode 'none')`, 마스크는 지금 그대로.
- 색: 사진에서 읽은 원래 색(`describeOutfitColors`)과 **같은 계열의 차분하고 살짝 다른 톤**.
  예) 진초록 → 올리브·카키. 색을 못 읽으면 지금처럼 무난한 색.
- 프롬프트가 이 지시를 얼마나 따르는지는 사용자가 직접 테스트한다.

## 이번에 안 하는 것

- 빠진 방식의 내부 함수(흐림·덮기·색만 바꾸기·마크 지우기·kontext 후처리)와 그 단위 테스트는
  남긴다. 화면에서 부르는 곳만 끊는다. 지우는 것은 다음 정리 때.
- 103장 재측정 없음. fal.ai 호출 없음 — 실제 결과는 사용자가 테스트.

## 확인

- 돈 안 드는 테스트로: 카드 2개, 자동 실행 없음, 돌리기 후 미리보기·`uploadedPhotoUrl` 크기 바뀜,
  EXIF는 원본에서, 배경 마스크에서 얼굴·손이 0픽셀 열림, 마스크 크기 = 보낼 크기(32 배수).
- 고쳐야 할 기존 테스트: `outfit-modes.js`, `pill-wrap.js`, `stack.js`, `cover-edit.js`,
  `background-replace-live.js`(실제 API — 돌리지 않고 요청 형태만 맞춘다).
