# C단계: Tesseract OCR → Claude Vision 전환 설계

Campus AX-Ton · 안심앨범

## 1. 배경

A단계에서 Tesseract.js OCR을 붙이고 전처리/PSM 튜닝을 거쳤지만, 실사진(`꽃집간판.jpg`)
기준으로 "꽃집 누아블룸" → "교지 누아블룸"처럼 여전히 오독이 남고, 전화번호·번지수·작은
로고는 아예 검출되지 않는 한계가 있었다 (`README.md` 6번 항목 참고). 이를 Claude Vision
(멀티모달 LLM)으로 대체해 실제 판독률을 높인다.

## 2. 핵심 요구사항

1. Claude Vision API(`claude-haiku-4-5-20251001`)로 이미지 속 텍스트를 읽는다.
2. **프라이버시 원칙 유지**: 얼굴은 외부로 전송하지 않는다 — face-api로 검출한 얼굴 영역을
   전송 전 마스킹한다.
3. API 키는 브라우저에 노출되지 않는다 — 로컬 Express 백엔드가 중계한다.
4. 평소 흐름은 Claude Vision 하나만 쓰지만, 실패 시 자동으로 Tesseract 결과로 전환해
   데모 중 "아무 결과도 안 나오는" 상황을 막는다.
5. `?debug=1`에서는 항상 Tesseract와 Claude Vision을 **둘 다** 돌려서 텍스트·처리시간·
   신뢰도를 나란히 비교 표시하고, 같은 내용을 콘솔에도 로그로 남겨 여러 사진으로
   데이터를 모을 수 있게 한다 (발표 자료용).

## 3. 아키텍처

```
브라우저(index.html)                     로컬 백엔드(server/, Express)          Anthropic
─────────────────────                    ──────────────────────────           ─────────
1. face-api로 얼굴 bbox 검출 (기존)
2. 얼굴 영역을 검은 사각형으로 마스킹
3. 마스킹된 이미지(base64 JPEG) +   ──POST /api/analyze-image──▶  4. .env의 API 키로
   프롬프트를 백엔드로 전송                                          Messages API 호출 ──▶ Claude Vision
                                                              ◀── JSON 텍스트 응답 ──
                                    ◀── 파싱된 JSON 반환 ──────
5. 응답을 pin 렌더링 포맷으로 변환
   (9분할 위치 문자열 → xPct/yPct)
```

- 백엔드는 프론트(정적 파일, `python -m http.server 8000`)와 별도 포트(3001)에서 실행.
  CORS로 `localhost:8000` origin만 허용.
- 프론트 실행 방식(정적 서버)은 그대로 유지 — 백엔드는 순수 API 중계 역할만 한다.

## 4. 프라이버시: 얼굴 마스킹

- 이미 검출된 face-api bbox에 20% 패딩을 주고 **완전 불투명 검은 사각형**으로 채움
  (블러는 복원 가능성이 있어 배제 — 이건 2단계 "보정"의 자연스러운 블러와는 다른,
  "외부 전송용 비식별화" 목적이므로 안전한 쪽을 택함)
- 마스킹은 Claude Vision에 보내는 이미지에만 적용. Tesseract는 100% 로컬 처리이므로
  원본 그대로 사용 (비교 시 이 차이는 명시적으로 라벨링)

## 5. Claude Vision 연동

**요청 형식**: Anthropic Messages API, image content block(base64) + 텍스트 프롬프트.

**프롬프트** (사용자 지정):
```
이 이미지에서 보이는 모든 텍스트를 읽어줘.
간판, 표지판, 차량번호판, 전화번호, 주소 등 위치를 특정할 수 있는 정보에 특히 주의해줘.
각 텍스트의 대략적인 위치(상단/중앙/좌하단 등)도 함께 알려줘.

JSON으로 응답:
{
  "감지된텍스트": [
    {"내용": "꽃집 누아블룸", "위치": "상단 중앙", "유형": "상호명"},
    {"내용": "010-4956-6091", "위치": "상단 우측", "유형": "전화번호"}
  ]
}
```

**응답 파싱**: 텍스트에서 첫 `{...}` JSON 블록을 추출해 `JSON.parse`. 실패 시(형식이
깨진 응답) 폴백 트리거와 동일하게 처리(자동으로 Tesseract 결과 사용, 콘솔에 원문 로그).

**위치 → 좌표 변환**: "위치" 문자열을 9분할 그리드로 매핑
(상단/중앙/하단 × 좌측/중앙/우측 → 대략 (x%, y%) 중심점). 키워드 부분매칭으로
느슨하게 처리(정확히 9개 표현과 안 맞아도 "상단"/"좌측" 등 포함 여부로 판단).
**한계**: 픽셀 정확도가 아닌 9분할 근사 위치 — Tesseract 대비 핀 정밀도가 낮아짐
(합의된 트레이드오프).

## 6. 폴백 / 비교 동작

| 상황 | 동작 |
|---|---|
| 평소 (`?debug` 없음), Claude Vision 성공 | Claude Vision 결과만 사용 |
| 평소, Claude Vision 실패(네트워크/키/파싱 오류) | **자동으로 Tesseract 결과로 전환**, 사용자에게는 티 안 내고 정상 진행 (콘솔에는 실패 사유 로그) |
| `?debug=1` | 성공 여부와 무관하게 **Tesseract + Claude Vision 둘 다 실행**하고 비교표 표시 |

**비교표(디버그 패널)에 포함**: 각 방식의 인식 텍스트 목록, 처리시간(ms), 신뢰도
(Tesseract는 OCR confidence, Claude는 자체 신뢰도 개념이 없으므로 "제공 안 됨"으로
표시하거나 텍스트 일치율 같은 대체 지표를 고려 — 구현 시 확정).
**콘솔에도 동일 데이터를 구조화된 형태로 로그**(사용자가 여러 사진으로 테스트하며
발표 자료용 데이터를 수집할 수 있도록).
