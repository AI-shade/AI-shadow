# 말투 모음

비슷한 서비스들이 화면에서 어떤 말투를 쓰는지 모은 자료입니다. «말투» 작업 1단계(비슷한 서비스의 화면 문구 모으기)의 결과입니다.
2단계에서는 이 파일을 AI에게 보여 주고 우리 말투 규칙을 만듭니다.

- 모은 날: 2026-11-22
- 출처: 22곳 (말투 가이드 8곳, 개인정보·아동 안전 7곳, 검사 결과 7곳)
- 모은 방법: 로그인하지 않고 열리는 공개 페이지만 읽었습니다. 회원가입, 양식 제출, 사진 업로드, 검사 실행은 하지 않았습니다.
- 문구는 페이지에 적힌 그대로 옮겼습니다. 이미지 안에만 있는 글자는 이미지를 열어 읽고 옮겼습니다. 지어내거나 다듬은 문장은 없습니다.
- «관찰»로 표시한 줄은 모은 사람의 정리이고, 인용이 아닙니다.

종류 표시: 버튼 / 제목 / 안내 / 경고 / 결과 / 오류 / 빈 화면 / 동의·권한 / 기타.
검사 결과는 결과-위험 / 결과-안전 / 결과-일부 / 결과-확인못함 / 권장행동으로 더 나눴습니다.

## 차례

1. 말투 가이드: 회사가 공개한 원칙과 «고치기 전 → 고친 뒤» 예문
2. 개인정보·아동 안전 서비스의 화면 문구
3. 검사·진단 결과 문구
4. 규칙을 정할 때 고를 것 (출처끼리 다른 곳)
5. 못 연 곳

# 1. 말투 가이드

## 1-1. 토스: «토스의 8가지 라이팅 원칙들»
https://toss.tech/article/8-writing-principles-of-toss (2022-11-15)

**핵심 가치**
- Clear 명확한: 메이커가 아닌 사용자가 이해할 수 있는 문장을 쓴다.
- Concise 간결한: 꼭 필요한 내용만 필요한 만큼 전달한다.
- Casual 친근한: 어려운 용어와 딱딱한 뉘앙스를 쉽고 친절하게 고쳐 쓴다.
- Respect 존중하는: 코스트를 숨기거나 혜택을 부풀리지 않는다. 진실되게 쓴다.
- Emotional 공감하는: 사용자가 느낄 감정에 공감한다.

**원칙**
- Predictable hint: 다음 화면을 예상할 수 있는 힌트가 있는가?
- Weed cutting: 의미 없는 단어(잡초)를 모두 제거했는가? 예: "[혹시]는 의미 없는 단어다".
- Remove empty sentences: 화면이 허전해서 넣은 문장, 반복하는 문장을 뺐는가?
- Focus on key message: 정말 중요한 메시지만 전달하는가? 사용자가 이미 아는 정보는 생략한다.
- Easy to speak: 소리 내어 읽었을 때 어색하지 않은가? 한자어·문어체·긴 호흡을 피한다.
- Suggest over force: 특정 행동을 강요하거나 공포감을 주지 않는가?
- Universal words: 모두가 이해할 수 있고 모두에게 무해한가? 유행어·은어·밈을 피한다.
- Find hidden emotion: 정보 뒤의 감정에 공감했는가?

**예문** (페이지의 이미지에서 읽음)

| 고치기 전 | 고친 뒤 | 종류 |
|---|---|---|
| 다른 곳에서 후불결제 하기 | 내가 쓰는 브랜드 신청하기 | 버튼 |
| 앞으로 받을 배당금 | 받을 배당금 | 기타(목록 이름) |
| 요즘 20대가 자주 쓰는 인기 서비스 6개 / 발견한 인기 서비스를 써볼 수 있어요. | 요즘 20대가 자주 쓰는 인기 서비스 6개 (부제 삭제) | 안내 |
| 대출금의 원금을 갚습니다 / 원하는 금액만큼 대출금을 갚아요. 남은 대출금에 맞춰 월 상환금액이 자동으로 조절돼요. · 한 달치의 원금과 이자를 미리 갚을게요 / 다음 회차에 해당하는 원리금을 미리 낼 수 있어요. | 금액 직접 입력하기 · 다음 달 이자 미리 내기 | 버튼(선택지) |

| 지금 그만두면 무제한 연 1% 이자를 받을 수 없어요 / 토스증권 계좌는 한도 없이 이자를 매달 받을 수 있어요. [이어서 하기][나가기] | 다음에 할까요? / 토스증권 계좌는 한도 없이 연 1% 이자를 매달 받을 수 있어요. [닫기][나가기] | 기타(나가기 확인), 버튼 |

## 1-2. 토스: «좋은 에러 메시지를 만드는 6가지 원칙»
https://toss.tech/article/how-to-write-error-message (2022-09-21)
같이 읽은 글: https://toss.tech/article/introducing-toss-error-message-system

**원칙**
- 가장 중요한 가치는 Navigating이다. 사용자가 다음 단계로 무엇을 해야 할지 안내하는가?
- 에러 메시지에는 세 가지가 들어가야 한다: 상황 설명, 이유, 해결책.
- 최고의 에러는 발생하지 않는 것.
- 적절한 컴포넌트 쓰기. 위급하지 않은데 빨간색을 쓰지 않는다.
- 스스로 해결할 수 있는 방법 알려주기.
- 사용자 입장에서 이해할 수 있는 언어로 쓰기.
- 쉽게 해결할 수 있게 도와주기(버튼을 추가한다).
- 부정적인 감정 최소화하기. 안 되는 사실보다 할 수 있는 것을 말한다. "~해야 해요" 대신 "~할 수 있어요"로 권유한다.
- "(우리 잘못인데)에러 메시지에도 해요체를 적용해야 할까요?"에 대한 답은 "네!"다.

**예문**

| 고치기 전 | 고친 뒤 | 종류 |
|---|---|---|
| 비밀번호를 틀렸어요 | 김토스님의 정보가 아니에요 | 오류 |
| 내 연락처로는 돈을 보낼 수 없어요. | (메시지 없음. 연락처 목록에서 내 연락처를 빼서 에러 자체를 없앰) | 오류 |
| (토스트) 대출 심사 진행 중으로 KB저축은행 고객센터(0000-0000)로 취소 신청해주세요. | (다이얼로그) 전화로만 취소할 수 있어요 / 이미 심사를 시작했어요. 대출 신청을 취소하려면 KB저축은행 고객센터(0000-0000)로 문의해주세요. [닫기][전화하기] | 오류 |
| 생체 인증에 실패했어요. | 생체 인증 정보에 문제가 생겼어요 / 같은 문제가 반복된다면 앱을 껐다 켜거나 삭제하고 다시 설치해주세요. | 오류 |
| 알 수 없는 종류의 신분증입니다. | 기간이 만료된 신분증이에요 / 체류 기간이 만료된 외국인 등록증이에요. | 오류 |
| Request failed with status code 500 · 세션이 만료되었습니다. | (나쁜 예로만 실림) | 오류 |
| 하루에 한 번만 신청할 수 있어요 / …오늘 꼭 신청해야 한다면 고객센터(1599-4905)로 문의해주세요. [확인] | 문구는 같고 버튼만 [닫기][문의하기] | 오류, 버튼 |
| 신용 관리 서비스를 이용할 수 없는 연령입니다. | 신용점수는 만 19세 이상부터 확인할 수 있어요. | 오류 |

## 1-3. 토스 앱인토스 개발자센터: «UI/UX 가이드»의 UX 라이팅
https://developers-apps-in-toss.toss.im/design/consumer-ux-guide.md

**원칙**
- 제품 안의 모든 문구는 해요체로 쓴다. 상황·맥락을 불문한다.
- 능동형 문장을 쓴다. 수동형은 특정 상황에서만 쓴다. (됐어요 → 했어요)
- 부정 대신 긍정형으로 쓴다. 예: 안 돼요, 없어요 (X) → ~하면 할 수 있어요 (O)
- 서비스는 쓸 수 있는데 특정 혜택만 못 받을 때는 긍정형으로 쓴다. 사용자는 훑어보기 때문에 제품 전체를 못 쓴다고 오해하기 쉽다.
- 다이얼로그 왼쪽 버튼은 [닫기]로 통일한다. [취소]는 하던 작업이 취소된다고 오해할 수 있어 쓰지 않는다.
- 과도한 경어를 쓰지 않는다: ~시겠어요?, 시나요?, ~께.
- 경어를 빼서 어색해지면 파악하고 싶은 정보를 주어로 삼아 새로 쓴다.
- {명사}+{명사}를 쓰지 않는다. 한자어를 풀어 쓰거나, 최소한 '{명사}가 {명사}해서' 꼴로 푼다.
- '되어요'는 모두 '돼요'로 쓴다.

**예외 규칙**
- 수동형 허용: 서비스 종료·기간 만료, 사용자에게 미치는 영향(연체·해지·적용), 사용자 안심('정보 수집 안내' 등 민감한 상황).
- 경어 허용: 사용자 맥락을 활용한 질문, 사용자 상황을 추정할 때, 설문처럼 사용자의 선의가 필요할 때.
- 부정형 허용: 정책상 쓸 수 없을 때(이유를 함께 안내), 일부 기능만 쓸 수 없을 때, 사용자 안심('정보 수집 안내' 등).

**같은 페이지의 다크패턴 방지 정책**
- CTA 버튼만 보고 다음 행동을 예상할 수 있어야 한다.
- 거절할 수 있는 선택지를 둔다.
- 부정적이거나 애원·호소하는 감정 표현을 피한다.

**예문** (페이지의 이미지에서 읽음)

| 고치기 전 | 고친 뒤 | 종류 |
|---|---|---|
| 김토스님에게 1원을 보냅니다 | 김토스님에게 1원을 보낼게요 | 안내 |
| 알림이 설정됐어요. | 알림을 설정했어요. | 결과 |
| 새 비밀번호로 바뀌었어요 | 새 비밀번호로 바꿨어요 | 결과 |
| 카드론 평균 금리가 13%로 높아졌어요 | 카드론 평균 금리가 13%로 올랐어요 | 안내 |
| 보호자가 허락하기 전에는 가입할 수 없어요 | 보호자가 허락해야 가입할 수 있어요 | 안내 |
| 지금 버전에서는 쓸 수 없어요 / 생체 인증을 쓰려면 앱을 최신 버전으로 업데이트 해주세요. | 앱을 업데이트해주세요 / 생체 인증을 쓰려면 최신 버전이 필요해요. | 오류 |

| 계좌 개설 혜택은 받을 수 없어요 / …이번 혜택은 계좌를 처음 만드는 분에게만 드려요. | 4.5% 금리 혜택만 받을 수 있어요 / …(상품권, 주식) 혜택은 계좌를 처음 만드는 분에게만 드려요. | 안내 |
| 카드를 해지하시겠어요? | 카드를 해지할까요? | 기타(확인 질문) |
| 오늘 토스뱅크 시작하시는 분에게 5,000원을 드려요 | 오늘 토스뱅크를 시작하면 5,000원을 드려요 | 안내 |
| 자동차를 가지고 계시나요? | 자동차가 있나요? | 기타(입력 질문) |
| 안전한 개통을 위해 몇 가지 다시 여쭤볼게요 | 안전한 개통을 위해 몇 가지 다시 확인할게요 | 안내 |
| 어떤 이유로 신고하시나요? | 신고 이유를 선택해주세요 | 기타(입력 질문) |
| 내일 카드값이 결제될 예정이에요 | 내일은 카드값 나가는 날이에요 | 안내 |
| 잔액 부족으로 구매하지 못했어요 | 잔액이 부족해서 구매하지 못했어요 | 오류 |
| 김토스님께 | 김토스님에게 | 기타 |
| 매달 보험료 얼마씩 내고 계시나요? | 매달 보험료는 얼마인가요? | 기타(입력 질문) |
| 어떤 목적으로 대출받으시나요? | 대출 목적이 무엇인가요? | 기타(입력 질문) |
| 이자 환불을 받았어요 | 이자를 돌려받았어요 | 결과 |

## 1-4. 토스플레이스: 연동 가이드 «UX 라이팅»
https://docs.tossplace.com/guide/front-integration/plugin/design/ux-writing.html

**원칙**
- 쓰기 전에 이 화면을 누가 보는지 먼저 정한다. 손님은 처음 봐도 3초 안에 읽혀야 하고, 사장님·직원은 200번째에도 헷갈리지 않아야 한다.
- 모든 문구를 해요체로 쓴다. 상황과 맥락을 가리지 않는다.
- 능동적으로 쓴다. 완료 화면 제목도 명사로 끝내지 않는다(주문 완료 → 주문했어요).
- 긍정형으로 쓴다. 다음에 무엇을 할 수 있는지 같이 알려준다.
- 에러 문구에서는 오류 코드와 시스템 용어를 빼고 다음 행동을 알려준다.
- 다이얼로그의 왼쪽 버튼은 닫기다.
- 캐주얼한 경어를 쓴다. ~시겠어요?, ~계신가요?는 오히려 거리감을 만든다.
- 명사를 세 개 이상 이어 붙이지 않고 동사로 푼다.
- 버튼만 보고 무슨 일이 일어나는지 알 수 있어야 한다. 한 화면에서 '-하기'와 명사형을 섞지 않는다.
- 예와 아니요를 동등하게 둔다. 거절하면 손해 보는 것처럼 들리는 문구는 쓰지 않는다.
- 이모지는 쓰지 않는다. 같은 대상을 가리키는 말은 하나로 통일한다.

**예문**

| 고치기 전 | 고친 뒤 | 종류 |
|---|---|---|
| 결제가 완료되었습니다 | 결제했어요 | 결과 |
| 확인 바랍니다 | 확인해주세요 | 안내 |
| 적립이 완료되었어요 | 적립했어요 | 결과 |

## 1-5. 당근: SEED Design «Voice and Tone», «Writing»
https://seed-design.io/foundations/voice-and-tone
https://seed-design.io/foundations/writing

**원칙**
- 명확한, 이해하기 쉬운, 사려깊은. 보이스 톤은 "활기차고 친절한"이고, "이야기하듯 친근하게 말해요."
- 성별·나이·종교·혼인 여부·인종·장애 등 다양성을 존중한다. 말에는 정보뿐 아니라 감정도 담겨 있다.
- 익숙한 단어를 쓴다. 기술 용어나 한자어는 지양한다.
- 에러 메시지에는 직접 해결할 수 있는 방법을 알려준다.
- 존칭어 사용을 최소화한다. 정말 꼭 필요할 때만 쓴다.
- 수는 아라비아 숫자로 쓴다. 축약어·은어·속어·유행어는 지양한다(사용자가 '끌올'이라 불러도 우리는 '끌어올리기').
- 기능의 이름보다 기능의 목적을 전달한다. 같은 내용이면 긍정문을 쓴다. 능동문을 쓴다.
- 가이드보다 좋은 문장이 먼저다. 피동문이 의미를 더 잘 전달하면 피동문을 쓴다.
- **자동 발송 메시지이면서 사용자가 조심해야 하는 상황이면 '~요' 대신 '~니다'를 써서 문장에 무게를 싣는다.**
- 처리·완료 같은 데이터 변화보다 사용자의 행위를 표현한다.
- 하나의 목적에 집중한다. 한 문장에는 하나의 내용만 담는다.
- 느낌표는 꼭 필요한 순간에만 쓴다.
- 마침표는 메인 타이틀, 20pt 이상 큰 글씨, 버튼·메뉴·라벨에는 쓰지 않는다.

## 1-6. 강남언니: «UI 텍스트 가이드라인 제작기»

# 4. 규칙을 정할 때 고를 것

출처끼리 다른 곳입니다. 2단계에서 우리 쪽 답을 정해야 합니다. (모은 사람의 정리)

| 고를 것 | 출처별 선택 |
|---|---|
| 문체 | 해요체 통일: 토스, 토스플레이스, 당근. 합니다체: 강남언니, 스포카, 구글, 인스타그램. 섞음: 털린 내 정보 찾기, 밴드, 알약 |
| 조심해야 하는 안내의 문체 | 당근: 자동 발송되는 주의 메시지만 «~니다». 지우개·밴드: 법적 책임·경고 부분만 «~합니다» |
| «~하시겠어요?» | 쓰지 말라: 토스, 토스플레이스, 당근(존칭 최소화). «~습니까?»보다 낫다: 스포카 |
| 대화창 왼쪽 버튼 | [닫기]: 토스, 센스. [네] 대신 구체적인 동작(«작성 취소하기»): 스포카 |
| 버튼 꼴 | «-하기»와 명사형을 한 화면에 섞지 않기: 토스플레이스. «~하기» 권장: 스포카. 기능 이름보다 목적(«채팅으로 거래하기»): 당근 |
| 느낌표 | 적극: 강남언니, 알약. 꼭 필요할 때만: 당근 |
| 이모지 | 쓰지 않기: 토스플레이스 |
| 위험을 부르는 말 | «위험» 그대로: V3, 카카오. 급한 정도로(«긴급 알림 / 중요한 단계 / 보안 도움말»): 구글. «주의»로 낮춰서: 알약. «의심»으로 확정을 피함: 건강검진 |
| 결과 단계 수 | 2단계: 알약(안전/주의), V3(안전/위험). 색 3개 + 안전: 구글. 5단계: 건강검진 |
| 아무것도 못 찾았을 때 | «탐지된 항목이 없습니다»(알약), «권장사항이 없는 것입니다. 하지만 …»(구글)처럼 «못 찾았다»고 말하고 여지를 남김. V3는 그래도 의심되면 신고하는 길을 둠 |
| 검사를 못 했을 때 | 이유를 상태처럼 보여 줌(«업데이트 중 입니다», «미사용 중»). 건강검진은 판정에서 빼고 다시 찍게 함 |
| 사용자가 결과에 맞서는 길 | 바른한글 «오류 제보», V3 위협정보 신고센터, Chrome «경고 닫기 / 경고 복원», 알약 «오탐지» 언급 |
| 부모를 대하는 태도 | 세이브더칠드런: 공유하고 싶은 마음을 먼저 인정하고 «하지만»으로 넘어감. 정부 카드뉴스: «~하지 마세요» 명령형 |
| 부정형·수동형 예외 | 앱인토스: 정책상 못 쓸 때, 일부 기능만 못 쓸 때, 서비스 종료·만료, «정보 수집 안내» 같은 안심 상황에는 허용 |
