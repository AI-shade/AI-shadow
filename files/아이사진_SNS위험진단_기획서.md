# 아이 사진 SNS 위험진단 서비스 (가칭)

Campus AX-Ton 프로젝트 기획 문서

---

## 1. 문제 정의

부모가 아이 사진을 SNS에 올릴 때(셰어런팅), 다음과 같은 위험이 쌓임:

- 아이 얼굴이 선명하게 반복 노출되면서 신원 특정이 쉬워짐
- 배경에 유치원 이름표, 자주 가는 놀이터 등이 계속 나오면서 아이의 생활 패턴(어디, 언제, 자주 있는 곳)이 노출됨
- **사진 한 장은 괜찮아 보여도, 여러 장을 모아보면 "이 아이는 화·목요일 오후 3시에 이 놀이터에 있다"는 패턴이 만들어질 수 있음**
- 이는 유괴, 스토킹 등 실질적 위험으로 이어질 가능성이 있음

## 2. 핵심 아이디어

> "사진 한 장이 아니라, 여러 장의 게시물을 모아서 보면 보이는 위험을 부모 대신 짚어주는 서비스"

기존 프라이버시 도구들은 대부분 사진 한 장만 보고 판단하는데, 이 서비스는 **누적된 여러 게시물의 패턴까지 짚어주는 것**이 핵심 차별점.

---

## 3. 전체 흐름

### 0. 프라이버시 설계 원칙

- **원본 사진은 위험도 진단(1단계) 과정에서 절대 외부로 전송하지 않음**
- 얼굴/텍스트 등 개인정보 단서 추출은 **브라우저 내 로컬 비전 모델**로만 처리하고, 그 결과(비식별화된 수치·텍스트)만 Claude API로 전달
- 단, 실제 이미지 편집이 필요한 2단계(배경교체 등)는 이미지 자체를 처리해야 하므로 불가피하게 API로 전송되며, 이는 **사용자가 명시적으로 "보정하기"를 선택했을 때만** 발생
- **SNS 계정 연동·비밀번호 요구 없음** — 사용자가 직접 선택한 자료만 분석

### 1단계: 진단

1. 부모가 SNS에 올리려는 사진(+캡션) 업로드
2. **브라우저 내 로컬 비전 모델**로 개인정보 단서 추출 (원본은 외부로 나가지 않음):
   - face-api.js: 얼굴 각도, 프레임 대비 크기, 얼굴 개수
   - **Tesseract.js**: 이미지 속 텍스트 OCR — 간판, 표지판, 차량번호판 등 감지
3. 체크리스트로 맥락 정보 수집 (계정 공개범위, 업로드 시점, 타인 동반여부, 배경노출요소)
4. (선택) 과거 게시물 스크린샷 업로드 → 패턴 분석 (아래 1-2 참조)
5. **비식별화된 분석 결과(수치+감지된 텍스트 목록)만** Claude API에 전달 → 위험도 판단 + 근거 설명 + **패턴 경고**

#### 1-1. 위치 추정 위험도 점수

- **Tesseract.js(로컬 OCR)가 브라우저에서** 사진 속 위치 특정 단서를 텍스트로 추출:
  - 차량번호판, 간판·상호명·건물명, 도로표지판, 버스정류장 이름
- 추출된 텍스트 목록을 Claude API에 전달 (원본 이미지는 전송하지 않음)
- Claude가 각 단서별로 "이걸로 정확한 위치를 특정할 수 있는 정도"를 종합 판단해 점수화
- 예: "위치노출 위험도 82/100 — 감지된 텍스트 중 상호명이 포함되어 있어 특정 지역으로 위치 특정이 가능합니다"

**OCR 정확도 대응 (신규)**

한글 OCR은 기울어진 간판·작은 글씨·복잡한 배경에서 정확도가 떨어짐. 다음 전처리로 보완:

1. **흑백 변환 + 대비 강화** 후 OCR 실행
2. **텍스트 영역만 잘라내 확대** 후 재인식
3. **부분 인식도 단서로 활용** — 완벽한 판독이 목적이 아니라 "위치 특정 가능한 단서가 있는지" 판단이 목적이므로, "OO어린O집"처럼 부분 인식된 텍스트도 Claude에게 전달해 맥락 추론
4. Claude 프롬프트에 "OCR 결과가 부정확할 수 있으니 부분 인식 텍스트도 위치 단서로 판단하라"고 명시

#### 1-2. 스케줄 유출 경고 (핵심 차별점)

**입력 방식: 게시물 스크린샷 여러 장 업로드 (신규 확정)**

SNS 자동 연동은 불가능함 — Instagram Basic Display API가 2024년 12월 폐지되어 개인 계정 데이터 접근 경로가 없고, Graph API는 비즈니스·크리에이터 계정만 지원. 웹 스크래핑은 차단 대응 유지보수 부담이 크고 약관 위반 소지가 있음.

따라서 **사용자가 자기 게시물 스크린샷을 여러 장 업로드하는 방식**을 채택:

- 스크린샷에는 캡션 + 게시 시점("3일 전" 등) + 사진이 모두 포함되어 있음
- Tesseract.js로 캡션과 시점 텍스트를 추출 (화면 캡처라 폰트가 정면·선명해서 간판 OCR보다 인식률이 높음)
- 상대 시각("3일 전")은 스크린샷 업로드 시점을 기준으로 Claude가 역산
- 계정 연동·비밀번호 요구가 없어 프라이버시 원칙과 일치

*(보조 옵션) 원본 사진의 EXIF 촬영 일시 활용* — 스크린샷이 없거나 정확한 시각이 필요한 경우, 갤러리 원본 사진에서 EXIF를 읽어 보완. 단 SNS를 거친 사진은 EXIF가 제거되어 있을 수 있음.

**탐지 대상:**
- **요일 패턴**: 특정 요일에 반복되는 장소/활동 (예: "매주 화·목 오후 놀이터")
- **시간대 패턴**: 특정 시간대에 반복 노출되는 위치 (예: "오후 3~4시 하원길 반복 노출")
- **장소 반복**: 동일 장소가 여러 게시물에 걸쳐 등장
- **캡션 내 일정 정보**: "오늘부터 OO학원 다녀요", "매주 수요일은 태권도" 같은 명시적 스케줄 언급

**출력 예시:** "최근 게시물 5개를 분석한 결과, 매주 화·목요일 오후 3시경 OO놀이터에 계신 패턴이 반복적으로 노출되고 있습니다. 이런 정보가 누적되면 아이의 위치와 시간을 예측하기 쉬워질 수 있어요"

사진 단위 진단이 아니라 **여러 게시물을 누적 분석해야만 발견되는 위험**이라는 점에서, 이 서비스의 핵심 차별점.

### 2단계: 보정

위험도가 높으면 대응 옵션 제시. **블러를 기본으로 쓰지 않음** — 부모가 자랑하고 싶어 올리는 아이 사진에 블러가 있으면 실사용 가능성이 떨어지므로, 위험 유형별로 자연스러운 처리를 선택.

**위험 유형별 처리 방식 (신규)**

| 위험 요소 | 처리 방식 | 특징 |
|---|---|---|
| 가장자리 간판·표지판 | **스마트 크롭** | 결과물이 완전히 자연스러움. 아이는 보통 중앙에 있어 손실 적음 |
| 배경 전반의 위치 단서 | **배경 흐림(인물 사진 모드)** | 아이폰 인물모드처럼 보여 오히려 사진이 예뻐 보임. 거부감 없음 |
| 사진 한가운데 텍스트 | **flux-kontext-pro 교체** 또는 **스티커 덮기** | 스티커는 부모들이 이미 쓰는 익숙한 방식 |
| 캡션 속 주소/날짜 | Claude가 대체 문구 제안 | 같은 느낌 유지하며 구체 정보만 완화 |
| EXIF 위치정보 | 메타데이터 자동 삭제 | piexifjs |

**처리 방식 선택 UI**

- Claude가 진단 결과를 보고 "이 사진엔 크롭이 적합하다"고 **추천**
- 사용자에게 2~3가지 옵션과 **미리보기**를 함께 제시해 직접 고르게 함
- 부모가 마음에 드는 결과를 고를 수 있어야 실사용 가능성이 올라감

*(참고/실험적) 경량 노이즈 처리*: 브라우저에서 즉시 처리되는 픽셀 노이즈 — 완벽한 방어 아님, R&D 탐구 증거로만 발표에 활용

### 3단계: 검증

- 2단계 처리 결과물(이미지+수정된 캡션)을 **1단계와 동일한 파이프라인에 다시 통과**시켜 재진단
- Claude에게 "원래 어떤 위험요소가 있어서 어떤 처리를 했는지"를 함께 전달하고 확인:
  1. 원래 위험요소가 실제로 해결됐는지
  2. 처리 과정에서 새로운 위험요소가 생기지 않았는지
  3. **인물(아이)이 원본과 동일하게 보존됐는지 (신규)** — AI 배경교체 시 얼굴이 변형될 수 있으므로 반드시 확인
- 출력 예시:
  - "✅ 검증 완료: 배경의 간판 텍스트가 더 이상 보이지 않으며, 인물의 얼굴·포즈도 원본과 동일합니다"
  - "⚠️ 재검토 필요: 배경 교체 과정에서 아이의 얼굴 윤곽이 미세하게 변형되었습니다. 크롭 방식을 권장합니다"
  - "⚠️ 캡션 확인 필요: 제안된 문구에 시간 정보('이번 주말')가 여전히 남아있습니다"
- 이 "탐지 → 처리 → 재검증"의 폐쇄형(closed-loop) 구조는 1회성 처리보다 신뢰도를 크게 높임
- 기술적으로 1단계 파이프라인 재사용이라 추가 구현 부담이 크지 않음

## 4. AI(Claude) 역할이 명확한 지점

- **프라이버시 우선 설계**: 원본 사진은 로컬 비전 모델로만 처리되고, Claude에는 비식별화된 분석 결과만 전달 — 개인정보 보호 서비스임에도 정작 아이 사진 원본이 외부로 나가는 모순을 방지
- **다중 정보 종합 판단**: 이미지 특징(수치), 텍스트 감지 결과, 체크리스트 답변, 캡션 텍스트, 과거 게시물 이력 — 성격이 전혀 다른 여러 비식별 정보를 종합해 하나의 위험도를 판단하는 것은 규칙(if-else)으로 짜기엔 조합의 경우의 수가 너무 많음
- **불완전한 OCR 결과의 맥락 추론**: 부분 인식된 텍스트에서 "이게 위치 특정 가능한 단서인지" 판단하는 것은 단순 매칭을 넘어선 추론
- **스케줄 유출 경고**: 여러 게시물의 요일·시간·장소·캡션을 교차분석해 반복 패턴을 발견하는 것은 순수하게 맥락을 이해하고 추론하는 영역 — Claude가 아니면 할 수 없는 부분이며 이 서비스의 가장 핵심적인 차별점
- **처리 방식 추천**: 위험 요소의 위치·성격을 보고 크롭/흐림/교체 중 무엇이 적합한지 판단
- **처리 결과 재검증**: 처리된 결과물을 원래 위험요소와 대조하여 실제로 해결됐는지, 새로운 위험이 생기지 않았는지 스스로 재확인하는 폐쇄형 구조

## 5. 기술 스택 및 실현가능성

| 구성요소 | 기술 | 실현가능성 | 비고 |
|---|---|---|---|
| 얼굴 특징 추출 (로컬) | face-api.js (브라우저) | 매우 높음 | 프로토타입 실제 검증 완료 (94ms 처리) |
| 텍스트 추출 (로컬) | Tesseract.js (브라우저) | 높음 | 전처리(흑백+대비강화, 영역크롭확대) 필수 |
| 스크린샷 캡션·시점 추출 | Tesseract.js | 높음 | 화면 캡처라 간판보다 인식률 높음 |
| 위험도 판단 + 패턴경고 | Claude API (비식별 데이터만 전달) | 매우 높음 | API 키 확보 완료 |
| 체크리스트 UI | 단순 웹 폼 | 매우 높음 | 난이도 낮음 |
| 스마트 크롭 / 배경 흐림 | Canvas API (브라우저) | 매우 높음 | GPU 불필요, 즉시 처리 |
| 배경/텍스트 교체 | flux-kontext-pro (Replicate/Fal.ai) | 높음 | 이미지 전송 불가피 (2단계 한정, 사용자 동의 하) |
| 메타데이터 제거 | piexifjs | 매우 높음 | 검증된 방식 |
| 노이즈 실험(R&D용) | Google Colab Pro | 참고용 | 실제 서비스 기능 아님, 탐구 증거로만 활용 |

### Flux Kontext Pro 가격

| 제공처 | 가격 (이미지 1장당) |
|---|---|
| Black Forest Labs 공식 | $0.04 |
| Fal.ai | $0.04 (Pro) / $0.08 (Max) |
| Replicate | 약 $0.055 |
| SiliconFlow | $0.04 (Pro) / $0.015 (Dev) |

- 무료 할당량 없음, 신규 가입 시 소액 크레딧 제공되는 경우 많아 데모 테스트 커버 가능
- 평균 처리속도 약 7초 — 라이브 데모에 무리 없음
- 8주 개발+테스트+발표 전체 예상 비용: **1~2달러 수준**

## 7. 정직하게 밝힐 한계 (발표 시 언급)

- **SNS 자동 연동 불가**: Instagram Basic Display API 폐지(2024.12)로 개인 계정 자동 분석 경로가 없음. 사용자가 스크린샷을 직접 업로드하는 반자동 방식. 다만 이는 **계정 접근 권한이나 비밀번호를 요구하지 않는다**는 점에서 프라이버시 측면의 장점이기도 함
- **OCR 정확도 한계**: 한글 간판 인식은 각도·조명·글자 크기에 따라 편차가 있음. 전처리로 보완하되, 완벽한 판독보다 "단서 존재 여부 판단"에 초점
- **이미지 편집 품질 편차**: 배경교체는 복잡한 배경이나 작은 글자일수록 결과 품질 편차 존재. 3단계 재검증에서 인물 보존 여부를 반드시 확인하며, 품질이 불안정하면 크롭·흐림을 대안으로 제시
- **노이즈 처리는 실험적 기능**: 완벽한 방어가 아닌 참고 수준이며, R&D 검증 과정으로만 제시
