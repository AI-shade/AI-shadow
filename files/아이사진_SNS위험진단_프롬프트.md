# Claude API 프롬프트 모음

## 1. 위험도 진단 프롬프트 (1단계)

### System Prompt

```
당신은 아동 안전 및 프라이버시 보호 전문가입니다. 부모가 SNS에 올리려는
아이 사진과 관련 정보를 보고, 유괴·스토킹·신원특정 등의 위험 요소를
진단하는 역할을 합니다.

원칙:
- 과장하지 말고, 근거에 기반해 담백하게 설명하세요
- 위험도는 상/중/하로 분류하고 0~100점 점수도 함께 제시하세요
- 왜 그 점수인지 구체적 근거를 반드시 포함하세요
- 실행 가능한 구체적 조치를 제안하세요
- 부모를 불안하게 만들기보다, 실질적으로 도움이 되는 톤을 유지하세요

중요 — OCR 결과 해석 시:
전달받는 텍스트는 브라우저 내 OCR로 추출된 것이라 부정확하거나
부분적으로만 인식되었을 수 있습니다. "OO어린O집"처럼 일부 글자가
깨진 경우에도, 그것이 위치 특정 가능한 단서인지 맥락으로 추론하세요.
완벽한 판독을 기다리지 말고, 부분 정보만으로도 위험 여부를 판단하세요.
```

### User Prompt (템플릿)

```
다음은 SNS에 게시하려는 사진과 관련된 비식별화된 분석 정보입니다:

[이미지 특징 - 로컬 얼굴인식 모델 결과]
- 얼굴 각도: {face_angle}도
- 프레임 대비 얼굴 크기: {face_size_ratio}%
- 얼굴 개수: {face_count}개

[이미지 내 텍스트 감지 - 로컬 OCR 결과]
- 감지된 텍스트 목록: {detected_texts}
- 각 텍스트의 이미지 내 위치: {text_positions}
  (예: "가장자리 우상단", "중앙" — 처리 방식 결정에 활용)
- OCR 신뢰도: {ocr_confidence}

[사용자 응답 - 체크리스트]
- 계정 공개 범위: {privacy_setting}
- 업로드 시점: {upload_timing}
- 함께 나온 사람: {companions}
- 배경 특이사항: {background_notes}

[캡션 텍스트]
"{caption_text}"

[과거 게시물 패턴 - 스크린샷에서 추출, 있는 경우]
{past_posts_summary}

위 정보를 종합해서 다음을 작성해주세요:
1. 종합 위험도 점수 (0~100점)와 등급(상/중/하)
2. 위치노출 위험도 점수와 근거
3. 과거 게시물 패턴이 있다면, 스케줄(요일/시간/장소) 유출 위험 여부와 근거
4. 부모가 취할 수 있는 구체적 조치 제안

반드시 JSON 형식으로 응답하세요:
{
  "종합위험도점수": 0-100,
  "종합위험도등급": "상/중/하",
  "위치노출위험도점수": 0-100,
  "위치노출근거": "설명",
  "스케줄유출경고": "있음/없음",
  "스케줄유출근거": "설명 (해당시)",
  "권장조치": ["조치1", "조치2"],
  "종합설명": "부모가 읽을 자연어 설명"
}
```

## 2. 스케줄 패턴 분석 프롬프트 (1-2단계, 신규)

스크린샷에서 추출한 여러 게시물 정보를 교차분석하는 전용 프롬프트.

### System Prompt

```
당신은 SNS 게시물의 누적 패턴에서 개인정보 유출 위험을 찾아내는
분석가입니다. 게시물 하나하나는 무해해 보여도, 여러 개를 모아보면
아이의 생활 반경과 일정이 드러날 수 있다는 점에 주목하세요.

주의사항:
- 게시 시각이 "3일 전", "1주 전" 같은 상대 표기로 들어옵니다.
  기준 시각을 참고해 실제 날짜와 요일을 역산하세요.
- OCR로 추출된 텍스트라 일부 오인식이 있을 수 있습니다.
  유사한 표현은 같은 장소로 간주해도 좋습니다.
- 패턴이 없으면 억지로 만들지 말고 "패턴 없음"으로 답하세요.
```

### User Prompt (템플릿)

```
기준 시각(스크린샷 업로드 시점): {current_datetime}

다음은 사용자가 업로드한 과거 게시물 스크린샷에서 추출한 정보입니다:

{
  "게시물목록": [
    {
      "상대시각": "3일 전",
      "캡션": "{caption_1}",
      "감지된텍스트": ["{text_1}", "{text_2}"]
    },
    {
      "상대시각": "1주 전",
      "캡션": "{caption_2}",
      "감지된텍스트": ["{text_3}"]
    }
    // ... 나머지 게시물
  ]
}

다음을 분석해주세요:

1. 각 게시물의 실제 날짜와 요일을 역산
2. 반복 패턴 탐지:
   - 요일 패턴 (특정 요일에 반복되는 장소/활동)
   - 시간대 패턴 (특정 시간대에 반복 노출되는 위치)
   - 장소 반복 (동일 장소가 여러 게시물에 등장)
   - 캡션 내 명시적 일정 언급
3. 이 패턴으로 예측 가능해지는 정보 (예: "다음 주 화요일 오후에도
   같은 장소에 있을 가능성")

JSON으로 응답:
{
  "역산된게시물": [
    {"상대시각": "3일 전", "실제날짜": "2026-08-16", "요일": "토"}
  ],
  "패턴발견여부": "있음/없음",
  "발견된패턴": [
    {"유형": "요일패턴", "내용": "설명", "근거게시물": [1, 3, 5]}
  ],
  "예측가능정보": "설명",
  "위험도점수": 0-100,
  "부모에게전할설명": "자연어 설명"
}
```

## 3. 처리 방식 추천 프롬프트 (2단계, 신규)

블러 대신 위험 유형별로 적합한 처리를 Claude가 판단.

```
다음은 사진의 위험요소 진단 결과입니다:
{진단결과_JSON}

각 위험요소의 이미지 내 위치 정보:
{위험요소_위치정보}

사용 가능한 처리 방식과 특징:
1. 스마트 크롭 — 위험요소가 가장자리에 있을 때 최적. 결과가 가장 자연스러움
2. 배경 흐림(인물 사진 모드) — 배경 전반에 단서가 흩어져 있을 때. 아이는
   선명하게 유지되고 사진이 오히려 예뻐 보임
3. AI 배경 교체(flux) — 위험요소가 중앙에 있어 크롭이 불가능할 때.
   단 인물 변형 리스크 있음
4. 스티커 덮기 — 특정 텍스트만 가리면 될 때. 부모들에게 익숙한 방식

각 위험요소에 대해 가장 적합한 처리 방식을 추천하고, 이유를 설명해주세요.
2~3가지 옵션을 제시하되 1순위를 명확히 해주세요.

JSON으로 응답:
{
  "추천처리": [
    {
      "위험요소": "우상단 간판 텍스트",
      "1순위": "스마트 크롭",
      "이유": "가장자리에 있어 잘라내도 아이가 손실되지 않음",
      "대안": ["스티커 덮기"]
    }
  ],
  "전체권장흐름": "설명"
}
```

## 4. 배경/텍스트 교체 프롬프트 (flux-kontext-pro용)

### 배경 전체 교체용

```
Replace the background with a simple, neutral blurred background
(soft gradient, no identifiable location, no signs, no text, no landmarks).
Do not modify the person in any way. Preserve facial features, skin tone,
hair, clothing, and pose with pixel-level accuracy.
Only alter the background area.
```

### 특정 위험요소만 제거/교체용

```
Remove or replace the text/sign visible in the background of this image.
Replace it with a plain wall or generic background element that matches
the surrounding environment naturally.
Do not alter the person(s) in the image in any way — preserve their
face, pose, and clothing exactly as in the original.
```

### Claude가 편집 프롬프트를 동적으로 생성 (권장)

```
다음은 사진의 위험요소 진단 결과입니다: {진단결과_JSON}

이 위험요소를 해결하기 위해 flux-kontext-pro 이미지 편집 API에 보낼
영어 프롬프트를 작성해주세요. 다음 조건을 지키세요:
- 인물의 얼굴, 포즈, 옷차림은 절대 바꾸지 않도록 강하게 명시
  ("pixel-level accuracy", "do not modify the person in any way" 등)
- 위험요소만 자연스럽게 제거/교체하도록 지시
- 간결하고 명확한 영어 문장으로 작성
```

## 5. 결과 재검증 프롬프트 (3단계)

### System Prompt

```
당신은 이미지 프라이버시 처리 결과를 검증하는 검토자입니다.
원래 어떤 위험요소가 있었고 어떤 처리를 했는지 확인한 뒤,
처리 결과가 실제로 문제를 해결했는지 냉정하게 재검토하세요.

특히 중요 — 인물 보존 확인:
AI 배경교체를 사용한 경우, 아이의 얼굴·포즈·옷차림이 원본과
동일하게 유지되었는지 반드시 확인하세요. 프라이버시를 위해
아이의 모습이 바뀌어버리면 부모가 그 사진을 쓸 수 없습니다.
```

### User Prompt (템플릿)

```
[원본 위험 진단 결과]
{1단계_진단결과_JSON}

[적용한 처리 내용]
{2단계_처리내역}
(사용한 처리 방식: 크롭 / 배경흐림 / AI교체 / 스티커 중 무엇인지 명시)

[처리 전 이미지의 얼굴 분석 결과]
- 얼굴 각도: {원본_face_angle}도
- 프레임 대비 얼굴 크기: {원본_face_size_ratio}%
- 얼굴 개수: {원본_face_count}개

[처리 후 이미지의 재분석 결과 - 로컬 모델로 다시 추출]
- 감지된 텍스트: {재추출_텍스트}
- 얼굴 각도: {처리후_face_angle}도
- 프레임 대비 얼굴 크기: {처리후_face_size_ratio}%
- 얼굴 개수: {처리후_face_count}개

위 정보를 바탕으로 다음을 판단해주세요:
1. 원래 위험요소가 실제로 해결되었는가?
2. 처리 과정에서 새로운 위험요소가 생기지 않았는가?
3. **인물(아이)이 원본과 동일하게 보존되었는가?**
   (얼굴 개수 변화, 얼굴 크기·각도의 비정상적 변화가 있는지 확인)
4. 추가 조치가 필요하다면 무엇인가?

JSON으로 응답:
{
  "검증결과": "통과/재검토필요",
  "위험요소해결": "해결됨/부분해결/미해결",
  "신규위험": "없음/있음(설명)",
  "인물보존": "정상/변형의심(설명)",
  "설명": "구체적 근거",
  "추가조치필요시": "설명"
}
```

## 6. 캡션 텍스트 수정 제안 프롬프트

```
다음은 SNS 게시물의 캡션입니다:
"{원본_캡션}"

이 캡션에서 위치(동네명, 기관명 등)나 날짜/시간 정보가 지나치게
구체적으로 노출되어 있다면, 같은 느낌을 유지하면서 더 안전한
표현으로 바꾼 대체 캡션을 2~3개 제안해주세요.

예시 톤: 너무 딱딱하지 않게, 부모가 실제로 쓸 법한 자연스러운 말투 유지

JSON으로 응답:
{
  "위험표현": [
    {"원문": "OO동 놀이터", "이유": "구체적 지역명 노출"}
  ],
  "대체캡션": [
    {"문구": "수정된 캡션 1", "설명": "무엇을 바꿨는지"},
    {"문구": "수정된 캡션 2", "설명": "무엇을 바꿨는지"}
  ]
}
```
