# 아이SHADOW 어플화 작업 기록 — 2026-08-29

## 개요

두 갈래가 같은 작업 트리에서 동시에 돌았다. 이 노트는 **진단 정확도**와 **폰 어플화**
두 갈래를 모두 담는다. 두 갈래 다 `hyeon-latest` 브랜치에 쌓여 있고, **커밋은 했지만
아직 올리지(push) 않았다** — 사용자가 "올리지는 말고"라고 했다.

목표는 발표용이다: 폰 한 화면에 시각적으로 들어오는 화면을 만들어 시연·발표자료에 쓴다.

## 갈래 1 — 진단 정확도 (커밋 완료·배포됨)

정답표 103장(팀원 분류: A 위험 63 · B 숨은위험 8 · C 안전 32)으로 실제로 쟀다.

| | 값 |
|---|---|
| A 찾음 | 98% |
| B 찾음 | 8장 중 5장 |
| C 찾음(낮을수록 좋음) | 32장 중 19장 |
| 놓침 | **4 / 71** |

### 고친 것 셋

1. **장소 글자 판정을 한 곳으로** (`isPlaceWord`) — 채점·위험요소지도·좁혀짐 사슬이
   각자 좁은 목록을 갖고 있어 표지판·아파트명·차량번호판을 통째로 놓쳤다.
2. **못 읽는 명찰을 만점으로 세던 것** — 프롬프트가 판독 여부를 묻게 하고, 안 읽히면
   12점이 아니라 5점. 실측: 103장 중 **50장이 "안읽힘"**이었다.
   같이 고친 것: 소속 판정이 `종류 + 근거`를 이어붙여 검사해서 **부정문에 걸렸다** —
   `근거: "일반 사복으로 보임, 특정 기관의 교복·원복 특징 없음"` → 교복으로 채점.
3. **글자 없는 사진의 장소 인식** — 구글 비전을 쓰지 않고(원본을 보내므로) 이미 사진을
   보고 있는 Claude에게 물었다. 남산타워·한강·N서울타워를 실제로 짚었다.
   이름을 지어내는 것을 셋으로 거른다: 두루뭉술한 말 / "또는·유사" 얼버무림 /
   **고유명사가 없는 것**("어린이집/유치원"은 이름이 아니라 종류다).

### 반드시 알아야 할 것 — 흔들림

**같은 사진이 매번 같게 읽히지 않는다.** 코드를 안 바꾸고 두 번 돌리면 103장 중
7장(6.8%)의 판정이 뒤집힌다. 그래서 **흔들림이 안 끼는 재는 법**을 만들었다:
같은 실행의 **같은 판독**을 판정 규칙 두 개로 채점한다
(`test/photo-accuracy.js`의 `앱자`/`옛자`). 판정 로직을 고쳤다면 이 방법으로 재라.

```
옛 규칙  놓침 8장 / 오탐 19장
새 규칙  놓침 4장 / 오탐 19장     ← 판정 로직만 다르게 채점
```

**주의:** 고침 1·3번은 이 세트의 출력을 보고 만들었다. 그러니 위 숫자는 순수한
홀드아웃 값이 **아니다.** 보고할 때 반드시 같이 말할 것.

### 무엇이 바뀌었나

폰 폭(또는 손가락으로 쓰는 납작한 화면)에서 **하단 탭바가 있는 앱**이 된다.
데스크톱은 손대지 않았다 — 긴 스크롤 페이지와 핀 고정 연출 그대로다.

**진단 결과 — 위/아래 두 칸** (사용자 요청):

```
┌──────────────────┐
│ 사진 + 번호 마커   │  위 절반
├──────────────────┤
│     오각형        │  아래 절반
│  60/100    ■ 중   │
└──────────────────┘
[ 보정 방식 선택하기 ]
[ 진단 과거글 ＋ 알아보기 문답 ]
```

실측(390x844): 두 칸 439px / 바 위 자리 662px.
점수 내역·할 일은 그 아래로 흘려보낸다 — **첫 화면이 무엇을 말하느냐**가 요구사항이다.

**보정** — 원본/처리 후 나란히(라벨은 캡션), 방식 2×2 타일(선택은 검은 테두리),
⚠원본 전송 배지는 타일 맨 위, 옷 색·교복 티는 칩 줄(선택은 검은 알약).

**알아보기·문답** — 큰 카드를 카드 안 행 목록으로(번호/아이콘 + 제목 + 설명 + ›).

## 발견한 문제와 해결

- **`order`가 안 먹었다.** `showScreen`이 인라인 `display:block`을 주는데 그게 `flex`를
  이겨서다. 보정 화면이 이미 쓰던 `:not([style*="none"]) { display:flex !important }`로 맞췄다.
- **표시 없는 섹션이 모든 탭에 샜다.** 히어로 779px · 자가점검 869px · 유도 띠 · 푸터
  579px가 알아보기 탭에 그대로 떠 있었다. `data-tab-of`를 붙였다.
- **데스크톱에 폰 전용 단추가 보였다.** `#screen-verify > button`(1,0,1)이
  `.ghost-link.clamp-more`(0,2,0)를 이겨서다. `:not(.clamp-more)`로 예외를 뒀다.
- **어두운 바탕에 어두운 글씨.** 히어로를 다크 카드로 바꾸니 오각형 축 값(`22/22`)이
  `--ink`라 통째로 안 보였다. **화면을 눈으로 안 봤으면 못 잡았다.**
- **오각형이 118px로 쪼그라들었다.** 460px 이하에서 크기를 못박는 규칙이 `max-width`를
  이겨서다. `width/height`를 같이 적어 244px로.
- **한글 파일명이 bash에서 깨진다.** `발표시안.mp4`를 ffmpeg에 못 넘겼다. 파이썬으로
  ASCII 경로에 복사한 뒤 처리할 것.
- **테스트가 거짓 통과하고 있었다.** `actions: ['a','b','c']` — 한 글자짜리로 재니
  「지금 할 일」이 35px로 나왔다. 실제 문장으로 바꾸니 831 → 889px로 넘쳤다.
- **높이만 재는 검사는 «바가 글자를 덮는 것»을 못 잡는다.** 좌표로 재면 이번엔
  스크롤 착지 위치에 따라 흔들린다(14px에도 65px에도 내려앉음).
  → **"내용 높이 vs 바 위에 남는 자리"**로 잰다. 스크롤과 무관하다.

### 기준이 틀려서 고친 검사 셋

코드에 맞춘 게 아니라 **요구사항이 바뀌었거나 기준이 잘못돼서** 고쳤다.

- `phone-fit`: "전체가 844px에 들어가는가"는 **사진을 숨겨야만 통과한다.** 사진이
  이 화면의 주인공이라 기준 쪽이 틀렸다 → "사진과 오각형이 첫 화면에 같이 들어오는가".
- `device-switch`: "보이는 `[data-tab-of]`가 정확히 1개"는 한 탭에 섹션이 여럿이면
  거짓으로 깨진다 → "보이는 것이 전부 같은 탭인가".
- `pill-wrap`: 80px 하한은 예전 글자 크기에서 나온 값이다. 칩이 작아지며 77px이 됐지만
  이름은 한 줄에 멀쩡히 들어간다 → 픽셀 하한 대신 **넘침을 직접 잰다**.

## 갈래 3 — 발표자료 (Task 6, 끝남)

시연 사진을 **실제 아이 사진에서 AI로 만든 사진으로 바꿨다**(`사진 100장 분석/사진6.png`).
발표장 스크린에 실제 아이 얼굴을 띄우지 않으려는 것이고, 「아이 사진을 지키는 앱이
아이 사진을 함부로 안 쓴다」는 말도 같이 할 수 있다.

사진6을 고른 이유: 「햇살어린이집」이 입간판·대문 현판·가슴 명찰 **세 군데**에 있고
원복과 엠블럼까지 한 장에 있다. 「간판·주소」와 「소속」이 동시에 터진다.

실제로 돌린 결과(진단 1회 + fal 옷 손보기 1회 + 검증 1회):

```
진단   간판·명찰 등 4곳을 사진 위에 번호로
보정   가슴 마크 제거 + 오트밀&브라운  ($0.06, 24초)
검증   ⚠ 재검토 필요 — 두 모델이 모두
```

**검증 결과가 발표의 핵심이다.** 옷만 고쳤더니 간판 글자가 남았고 두 모델이 그걸
잡아냈다. 앱이 스스로 "아직 부족하다"고 말하는 장면이라, 심사 문답의
"AI가 놓친 위험은 어떻게 합니까?"에 화면 하나로 답이 된다.

| 파일 | 무엇 |
|---|---|
| `docs/아이SHADOW-시연.pptx` | 슬라이드 5장, 모핑 전환. **gitignore 대상** |
| `test/ppt-capture.tmp.js` | 실제 흐름을 돌려 화면 11장 캡처 |
| `test/ppt-record.tmp.js` | 같은 흐름을 영상으로 (92초, 구간 시각 JSON) |
| `test/ppt-board.tmp.js` | 폰 목업 판(HTML→PNG) |
| `test/ppt-deck.tmp.py` | pptx 생성 (python-pptx) |

### 폰 목업이 «그냥 사각형»으로 보이던 것

원인이 둘이었고 **두 번째가 진짜였다**:
1. `ROUNDED_RECTANGLE`의 `adjustments`는 짧은 변 대비 비율이다. 0.055는 거의 각졌다
   (HTML 판은 폭 300px에 반지름 44px = **0.147**).
2. **스크린샷이 각진 사각형이라 프레임의 둥근 모서리를 덮었다.** 프레임을 아무리
   둥글게 해도 소용없다. Pillow로 **그림 파일 자체를 깎아** 알파를 넣었다
   (1170px 캡처에 반지름 105px = CSS 35px).
그리고 다이나믹 아일랜드·홈 인디케이터를 얹어야 «아이폰»으로 읽힌다.

### 모핑으로 «슉슉»을 낸다 — 영상이 아니라

폰 도형에 슬라이드마다 **같은 이름**(`폰`)을 주면 파워포인트 모핑이 짝을 맞춰,
폰은 제자리에 있고 화면만 스르륵 갈린다. 판을 그림 한 장으로 넣으면 모핑이 안 걸리므로
프레임·화면·라벨을 각각 따로 놓아야 한다.

영상보다 이쪽이 발표에 안전하다 — 발표자가 속도를 100% 제어한다.

## 아직 안 끝난 것 / 다음 단계

- [ ] **푸시하지 않았다.** 커밋 8개가 로컬에만 있다. 사용자가 "올리지는 말고"라고 했다.
- [ ] **영상 배속을 못 만들었다.** 녹화(92초)는 됐는데 자르고 빨리감기가 안 된다 —
      Playwright에 딸린 ffmpeg가 최소 빌드라 **출력은 webm/PNG뿐이고
      `setpts`·`fps` 필터도, image2 입력 디먹서도 없다.** 세 가지 우회를 다 시도해 전부 막혔다.
      제대로 하려면 `npm i -D ffmpeg-static`(약 80MB 다운로드)이 필요하다 —
      다운로드는 사용자 허락을 받아야 한다.
- [ ] `발표시안.mp4`를 **아직 못 봤다.** HEVC(아이폰 기본)라 이 환경의 ffmpeg·크로미움이
      둘 다 못 연다. 사용자가 준 **캡처 두 장**으로 의도는 파악했다(폰 목업 + 라벨 말풍선).
- [ ] **겹쳐 쌓기로 «통과»까지 가는 회차.** 지금은 옷만 고쳐 재검토가 떴다.
      「자연스럽게 덮기」로 간판 글자까지 덮으면 통과로 끝나는 회차도 만들 수 있다.
- [ ] **옷 손보기에서 덮기 편집 상자가 결과 위에 남는다.** 코드 주석을 보면
      「어떤 방식에서든 상자가 보인다」가 **의도된 동작**이라 임의로 안 고쳤다.
      다만 옷 손보기에서는 그 상자가 결과에 아무 영향이 없다. 사용자 판단이 필요하다.
- [ ] 알아보기·문답·과거글 탭에는 **앱바가 없다**(진단·보정·검증에만 있다).
- [ ] 놓침을 사용자가 신고할 길이 없다 — 오탐만 뺄 수 있다. 구조가 거꾸로다.
- [ ] 오탐 19/32. 명찰 50장은 5점으로 낮췄지만 여전히 "찾음"으로 센다.

## 주의사항

- **커밋·푸시는 사용자가 요청할 때만.** 지금은 커밋만 되어 있다.
- **다른 세션이 같은 작업 트리를 쓴다.** `index.html`을 고치기 전에 `git status`를 볼 것.
  같은 줄을 동시에 고치면 한쪽이 조용히 사라진다.
- **API 키를 출력·인용·전송하지 말 것.** 사용자가 채팅에 붙여넣은 적이 있고 교체하지
  않기로 했다. `server/.env`에서 `process.env`로만 읽는다.
- `아이사진*.jpg`·`childphoto.jpeg`·`wed.jpg`는 **실제 아이 사진**이다. 커밋 금지.
  화면 캡처가 필요하면 도형으로 만든 임시 그림을 쓸 것(이번 작업에서 그렇게 했다).
- **데스크톱을 건드리지 말 것.** 폰 규칙은 전부 어플 배치 미디어 블록 안에 있다.
  `pinned.js` 45개가 그 경계를 지킨다.
- 나머지 규약은 `AGENTS.md`에 있다 — 특히 1절(마스크 순서·원본 동의·판정을 한 곳에·
  산문을 키워드로 검사하지 않기)과 6절(한글 경로·CRLF·heredoc 인코딩).
