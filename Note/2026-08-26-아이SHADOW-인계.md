> 이 문서 하나만 읽어도 이어서 작업할 수 있게 썼습니다. 다른 노트를 찾아볼 필요 없습니다.

## 개요

**아이SHADOW**는 부모가 아이 사진을 SNS에 올리기 전에 개인정보 노출 위험을 **진단 → 보정 → 재검증**하는 한국어 단일 페이지 웹앱입니다. Campus AX-Ton(멋쟁이사자처럼) 해커톤 출품작입니다.

핵심 아이디어는 "이미 올라간 사진을 지우는 것"이 아니라 **올리기 전에 개입**하는 것입니다. 사진 한 장에서 간판·주소 같은 위치 단서, 교복·명찰 같은 소속 단서, 캡션의 일정 정보를 찾아내고, **아이는 건드리지 않은 채** 위험한 부분만 고칩니다.

이 세션에서는 주로 (1) 사용자 제보 버그 수정, (2) fal.ai 비용·용량 최적화, (3) GSAP 모션 추가, (4) 발표 준비를 했습니다. **커밋은 하나도 하지 않았고 배포도 안 했습니다** — 아래 주의사항 참고.

### 실행 방법

```bash
cd server && node server.js        # 3001번 — API 포함, 여기로 접속해야 AI가 동작

```

**중요**: 프런트가 `/api/...` 상대경로로 호출하므로 **8000번으로 열면 AI 기능이 전부 404**입니다. 실제 사용은 반드시 `localhost:3001`. 이걸 몰라서 "API가 죽었나?"로 한참 헤맸습니다.

## 아키텍처에서 반드시 알아야 할 것

### 안전 설계 4원칙 (제품의 정체성)

1. **얼굴은 가려서 보냅니다** — 진단용 외부 전송 시 얼굴을 먼저 검게 덮음
2. **부탁이 아니라 차단** — AI에게 "아이를 바꾸지 마"라고 프롬프트로 부탁하는 대신, **마스크에서 아이 영역을 빼버림**. 모델이 접근할 수단 자체가 없음. ← **이게 이 프로젝트의 핵심 차별점입니다. 절대 프롬프트 방식으로 되돌리지 마세요.**
3. **비율은 원본 그대로** — 어떤 보정을 거쳐도 사진 비율 불변
4. **고친 다음 다시 검사** — 같은 검사를 한 번 더 통과시켜 확인

### 마스크 규약

- 흰색 = AI가 새로 그릴 영역, 검은색 = 원본 보존 (fal 문서에 없어서 실제 호출로 확인함)
- `buildClothingMask`는 **얼굴·머리·목을 마지막에 검게 덮습니다.** 순서를 바꾸면 AI가 아이 얼굴을 다시 그립니다 — 이 앱에서 가능한 가장 나쁜 실패입니다.
- 마스크 테스트 48개(`outfit-mask` 14 + `inpaint-mask` 16 + `person-mask` 13 + `person-guard` 5)가 이걸 지킵니다.

### 위험도 채점

5개 항목, 합계 100점. 서버가 항목별로 받아서 더합니다(모델이 총점만 내놓으면 근거를 댈 수 없어서).

```
간판·주소 노출 26 / 소속 노출 22 / 인물 식별성 18 / 캡션 노출 18 / 게시 습관 16
```

API가 실패하면 브라우저에서 찾은 글자·얼굴만으로 **같은 5항목을 채운 대체 결과**를 만듭니다 (`buildMockDiagnosis`, `isFallback: true`). `test/fallback.js` 95개가 이걸 검사합니다.

### 스크롤 구조

- 핀 고정은 **CSS `position: sticky`**가 하고 JS는 "지금 몇 번째 항목인가"만 정합니다. 스크립트가 죽어도 무대는 붙어 있습니다.
- `.reveal` 클래스는 **JS가 붙입니다. HTML에 직접 쓰면 안 됩니다** (안 붙으면 영원히 `opacity: 0`).
- GSAP ScrollTrigger를 쓰지만 **ScrollSmoother는 절대 쓰면 안 됩니다** — 아래 참고.

## 이번 세션에 한 작업

### 수정한 버그

**1. 주변색 덮기가 회색으로 칠해지던 문제 (두 가지 원인, 둘 다 수정)**

- **원인 A**: `sampleBoxSurround`가 둘레 픽셀의 **평균**을 썼습니다. 밝은 벽 + 어두운 문이 반씩 걸리면 평균은 사진 어디에도 없는 중간 회색이 됩니다.
  → **중앙값**으로 변경 (채널별 256칸 히스토그램, 정렬 없이 O(n)).
  실측: 실제 아이 사진 8곳에서 바로 옆 픽셀과의 RGB 거리 합 **149 → 78**, 최악 **42 → 9**.

- **원인 B (이게 사용자가 겪은 진짜 증상)**: `labelBrushBlobs`가 320px 축소본에서 덩어리를 나누는데, **가는 붓으로 큰 사진에 칠하면 획이 축소 과정에서 사라져** 덩어리가 0개가 됐습니다. 그러면 대체 경로로 빠져 `rgb(128,128,128)`을 칠했습니다.
  재현: `4032x3024`에 반지름 5px → 덩어리 0개.
  → 못 찾으면 **1600px로 올려 재시도**, 그래도 못 찾으면 자국 전체 둘레에서 색을 뽑음. **어떤 경우에도 회색은 안 칠합니다.**
  회귀 테스트를 `test/patch-fill.js`에 추가했습니다(19 → 21개).

**2. "글자로 장소가 적혀 있다"가 항상 꺼져 있던 문제**

`renderLocationChain`이 `상호명|간판|주소|지번|전화번호` **다섯 낱말만** 통과시키는 화이트리스트를 썼습니다. Claude가 붙이는 `유형`은 자유 문구라 `학교명`·`현수막`·`기관명` 등이 얼마든지 옵니다. 그래서 사진에 "○○중학교"가 대문짝만하게 찍혀 있어도 "없음"이 떴습니다.
→ `isPlaceWord(w)` 도입. **유형과 내용을 같이 봅니다.** 둘 다 못 가려도 사진에 글자가 있으면 "없음"이라 단정하지 않습니다(놓치는 쪽이 잘못 잡는 쪽보다 나쁨).

**3. 검수 체크박스만 눌러도 AI 재호출이 나가던 문제**

체크박스 `change` 핸들러가 `selectMethod(currentMethod)`를 무조건 불러서, **체크만 해도 fal.ai 요금이 나가고 원본이 또 전송**됐습니다.
→ 브라우저 안에서 끝나는 방식(흐림·덮기)은 즉시 재렌더, **AI 방식은 "고른 것으로 다시 만들기" 버튼을 눌렀을 때만** 호출. 옷 바꾸기는 이 목록을 안 쓰므로 아무것도 안 함.

**4. 새로고침하면 페이지 한복판에서 시작하던 문제**

메뉴를 누르면 주소에 `#tool` 같은 앵커가 남고, 그대로 새로고침하면 브라우저가 그 자리로 점프했습니다.
→ `performance.getEntriesByType('navigation')[0].type === 'reload'`일 때만 앵커를 떼고 맨 위로. 링크로 들어온 경우는 그대로 앵커로 갑니다.

**5. AI 동의 모달 문구가 사실과 달랐던 문제**

"전송된 이미지는 처리 후 저장되지 않아요"라고 적혀 있었는데 **fal.ai 방침에 그런 약속이 없습니다.**
→ 실제 방침으로 교체: 권리는 올린 사람에게 / 모델 학습에는 안 씀(개선엔 익명·집계 사용 기록만) / **"처리 후 바로 삭제"는 약속 안 함**(계정 닫으면 30일 내, 2년 미사용 시 삭제 — 여기서 쓰는 건 우리 팀 계정) / 원문 링크. 폭도 400 → 580px로 넓혀 버튼이 스크롤 없이 보이게 했습니다.

**6. 사진 미리보기가 스크린샷 업로더를 덮던 문제** — `.up-part.has-preview { flex: 0 0 auto }`로 해결.

### fal.ai 비용·용량 최적화 (중요)

`runOutfitSwap` / `runInpaintRegions`가 **휴대폰 원본(12MP)을 그대로 fal에 보내고** 있었습니다.

| | 이전 | 지금 |
|---|---|---|
| 요청 크기(base64) | 4~6.6MB — **Vercel 4.5MB 한도 초과** | ~0.6MB |
| 처리 시간 | 40~60초 — **Vercel 60초 한도 아슬아슬** | 10~20초 |
| 1회 비용 | $0.60 | $0.09 |

→ `falSendSize(ow, oh)`로 긴 변을 **1568px**(진단용 `VISION_MAX_SIDE`와 동일)로 제한.
두 함수는 원래부터 "보낼 크기(`sw/sh`) vs 원본 크기(`ow/oh`)"를 분리하는 구조였고 얼굴 좌표 환산·마스크 생성·원본 복원이 이미 다 돼 있었습니다. `sw = ow`라 그 기능이 놀고 있었을 뿐입니다.

추가로 `compositeThroughMask()`를 넣어 **AI 결과를 마스크 안쪽에만 얹습니다.** 바깥은 원본 픽셀 그대로 — 실제 호출에서 배경 영역 **13,500픽셀 중 달라진 픽셀 0개**. 예전에는 FLUX가 사진 전체를 재인코딩해서 안 건드릴 곳까지 뭉갰으므로 **화질도 오히려 좋아졌습니다.**

**AI 배경 교체(`flux-pro/kontext`)는 손대지 않았습니다** — 사진 전체가 AI 결과라 축소하면 최종 해상도가 떨어집니다. 대신 Vercel 4.5MB 문제가 그대로 남아 있습니다(아래 다음 단계 참고).

## 발견한 함정 (다시 밟지 마세요)

- **ScrollSmoother는 쓰면 안 됩니다.** GSAP 3.13부터 무료지만, 페이지 전체를 `transform`으로 밀기 때문에 **`position: sticky`가 전부 깨집니다.** 실측: `.site-nav` top −3450, 핀 무대 top −600. 상단 네비 + 핀 고정 섹션 4개가 다 죽습니다. 쓰려면 sticky 핀을 전부 ScrollTrigger `pin: true`로 갈아엎어야 하고, `pinned.js` 45개 포함 테스트도 다시 짜야 합니다. **ScrollTrigger 자체는 안전합니다** — 문제는 ScrollSmoother뿐.
- **8000번 포트에는 `/api`가 없습니다.** 정적 서버라 AI 기능이 전부 404. 실사용은 3001번.
- **`.env`를 바꾸면 서버를 재시작해야 합니다.** 키를 바꿔놓고 재시작을 안 해서 예전 키로 계속 호출된 적 있습니다.
- **fal 잔액이 0이면 계정이 잠깁니다.** 증상은 업로드 단계에서 `403 Forbidden` — `"User is locked. Reason: Exhausted balance"`. 키를 바꿔도 소용없고(잠긴 건 계정), 충전해야 풀립니다. 잔액 확인: `GET https://rest.alpha.fal.ai/billing/user_balance` (헤더 `Authorization: Key <FAL_KEY>`).
- **`w.type`으로 정확 문자열 비교를 하지 마세요.** Claude가 붙이는 유형은 자유 문구입니다. `isSignboardText`의 `w.approximate` 분기에 아직 `w.type === '상호명' || w.type === '간판'` 정확 비교가 남아 있습니다 — **같은 종류의 버그가 잠재해 있습니다**(아래 다음 단계).
- **한글 접근 코드는 헤더에 그대로 못 넣습니다.** HTTP 헤더는 ASCII 전용 — `encodeURIComponent` + 서버 `decodeURIComponent`로 처리돼 있습니다.
- **셸 heredoc에서 `\\n`이 접힙니다.** Python 패치 스크립트로 JS 문자열의 `\n`을 다룰 때 `chr(92) + 'n'`으로 만들어야 합니다. 두 번 당했습니다.
- **컴퓨터 절전/포트 충돌로 서버가 조용히 죽습니다.** 테스트가 갑자기 실패하면 먼저 3001·8000이 살아 있는지 확인하세요.

## 주의사항

**보안 — 반드시 지킬 것**

- `server/.env`에 **실제 API 키**가 있습니다(`ANTHROPIC_API_KEY`, `FAL_KEY`). gitignore 되어 있고 추적되지 않습니다. **절대 커밋하지 마세요.**
- **커밋 전 `bash scripts/check-secrets.sh`를 반드시 실행하세요.** 이 세션에서는 매번 실행했고 전부 통과했습니다.
- `childphoto.jpeg`, `아이사진1/2/3.jpg`, `wed.jpg`는 **실제 아이 사진**입니다. `.gitignore`에 파일명으로 고정돼 있습니다. **절대 커밋하지 마세요.** 로컬 테스트 전용입니다.
- **API 키를 채팅에 붙여넣지 마세요.** 사용자가 직접 `server/.env`를 편집하는 방식으로 진행했습니다. 에이전트가 키 값을 다루지 않습니다.
- AI 경로(`outfit`, `ai`)는 **원본 사진을 fal.ai로 전송**합니다. 앱 내 동의를 받는 문서화된 예외입니다. 동의 없이 전송하는 경로를 새로 만들지 마세요.
- 유료 작업은 실제 돈이 나갑니다. **쓰기 전에 사용자에게 물어보세요.**

**사용자의 명시적 요청**

- **"배포는 하지 마" — 이 지시가 유효합니다.** 수정할 게 많다고 했고, 그 이후로 배포하지 않았습니다.
- 배포본: `https://child-molla2.vercel.app` (접근 코드 `qwerty` — 약한 코드라는 점은 사용자에게 알렸음)
- 사용자는 **한국어**로 소통합니다. 코드 주석도 한국어입니다.
- 사용자가 뭔가를 잘못된 자리에 넣었다고 하면 **되돌리기를 우선**하세요. 이 세션에서 두 번(세로 눈금, 인스타 피드 핀 고정) 되돌렸습니다.

**코드 규약**

- 주석은 **왜 그렇게 했는지**를 적습니다. 실측값이 있으면 숫자를 같이 적습니다(예: "실측: 7145에 멈췄는데 목표는 9669").
- 새 기능에는 회귀 테스트를 붙입니다. 사용자 제보 버그는 **반드시** 테스트로 박아둡니다.
- `index.html`은 크지만 **한 파일 구조를 유지**하고 있습니다. 빌드 도구를 도입하지 마세요.
