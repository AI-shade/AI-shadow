# 아이SHADOW 발표자료 수정 — 2026-08-31

## 개요

전날(08-29~30) 세션이 팀원 스토리텔링 덱과 우리 시연 데이터를 합쳐
`docs/아이SHADOW-발표.pptx`를 처음 만들었다. 이 대화는 그 덱을 사용자가
실제로 열어보고 준 피드백을 하나씩 반영하는 세션이다 — 새 기능 추가가
아니라 **이미 있는 파일을 계속 고치는 작업**이고, 대부분의 수정은
`test/ppt-merge.tmp.py`(팀원 원본 `docs/아이SHADOW_발표_스토리텔링  -
복구됨.pptx`을 매번 처음부터 다시 읽어 최종 pptx를 새로 만드는 스크립트)를
고치고 다시 실행하는 방식으로 이뤄진다.

**이 스크립트는 멱등이다** — 실행할 때마다 팀원 원본에서 시작해 모든 수정을
순서대로 재생하므로, `docs/아이SHADOW-발표.pptx`를 직접 손으로 고치면
다음 실행 때 사라진다. 반드시 `ppt-merge.tmp.py`를 고치고 다시 돌릴 것.

```
python test/ppt-merge.tmp.py
```

## 발견한 문제와 해결

- **파워포인트 클릭 애니메이션이 인식 안 됨.** `<p:timing>`을 python-pptx가
  지원 안 해서 raw XML로 손수 작성했다(도형 22개, 3클릭 그룹). 구조 검증(도형
  참조 정상, 스키마 순서 transition→timing 정상)은 다 통과했는데, 실제
  파워포인트에서 열어보니 **클릭하면 애니메이션 없이 바로 다음 슬라이드로
  넘어감** — 파워포인트가 이 timing을 아예 인식 안 했다는 뜻. python-pptx로
  검증할 방법이 없어서 더 파고들지 않고 포기, 이 덱이 이미 쓰는 검증된
  방법(모핑)으로 갈아탐. **관련 코드는 완전히 제거했다** — 파일에 남아있지
  않음.
- **슬라이드를 순서 재배치 뒤에 추가하면 파일이 깨진다.** 8번을 8a/8b로
  쪼개면서 `add_slide()`를 순서 재배치(`순서 = [...]` 코드, 650줄 근처) *뒤에*
  호출했더니 python-pptx가 다음 슬라이드 파일 이름(slideN.xml)을 잘못
  계산해서 **zip 안에 `slide11.xml`이 두 번 들어가는 손상**이 생겼다(zip이
  경고만 내고 저장은 됨 — 조용히 깨짐). 재현 테스트로 원인 확정: 순서
  재배치가 `len(prs.slides)`를 줄여놔서(드롭된 원본 슬라이드 하나 때문에)
  그 다음 `add_slide()`의 다음-파일이름 계산이 꼬인다. **해결: 슬라이드
  자체(빈 슬라이드)는 순서 재배치 *전*에 미리 만들어 자리를 예약하고, 내용
  채우기는 스크립트 뒤쪽(원래 자리)에서 한다.**
- **모핑도 안 나타나고 그냥 뜸.** `<mc:Choice Requires="p159">`만 있고
  `<mc:Fallback>`이 없었다 — markup-compatibility 규칙상 Fallback이 없으면
  구버전(또는 Choice를 못 읽는 쪽)이 `<mc:AlternateContent>` 전체를 무시할
  수 있다. `<p:fade/>` Fallback을 추가해서 다시 저장했다. **사용자가 이게
  고쳤는지 최종 확인은 안 했다** — 다음 세션이 이어받아야 할 부분.

## 주의사항

- **사용자가 파워포인트에서 직접 크기·간격을 조정할 수 있다 — 되돌리지
  말 것.** "사이즈나 간격 내가 조정할수도 있으니까 굳이 되돌리지마"라고
  명시적으로 말했다. 이 노트에 적은 구체적인 수치들(예: 06번 오각형
  높이 1800000, 08/09번 상자 높이 120/116/145 등)은 **이 세션이 정한
  기본값일 뿐 고정값이 아니다** — 사용자가 파워포인트에서 손으로 더
  조정했다면 그게 최신이고 맞는 값이다.
  - 바로 아래 항목("`ppt-merge.tmp.py`가 매번 처음부터 다시 만든다")과
    정면으로 부딪힌다: 스크립트를 그대로 재실행하면 사용자의 수동 조정을
    덮어써 버린다. **다음 세션이 이 스크립트를 다시 돌려야 할 일이
    생기면, 먼저 사용자에게 파워포인트에서 크기·간격을 따로 손본 게
    있는지부터 물어보고, 있다면 그 값을 스크립트에 반영한 뒤에 돌릴 것**
    — 묻지 않고 그냥 재실행해서 조용히 되돌리면 안 된다.
- **`docs/아이SHADOW-발표.pptx`를 손으로 고치지 말 것(위 항목의 예외 있음).**
  `test/ppt-merge.tmp.py`가 매번 팀원 원본에서 처음부터 다시 만든다 —
  스크립트를 고치지 않고 pptx만 손으로 고치면 다음 실행 때 사라진다.
  단, 사용자 본인이 파워포인트에서 크기·간격을 조정하는 것은 예외이며
  환영한다(위 항목 참고) — 다만 그 조정이 스크립트 재실행에 씻겨나가지
  않게 관리하는 게 다음 세션의 몫이다.
- **커밋·푸시는 사용자가 요청할 때만.** 이번 세션에서도 요청 없었음 — 아직
  커밋 안 됨(git status 확인 권장).
